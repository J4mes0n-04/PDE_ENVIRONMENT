# BUG-REPORT-CFG-001 — полный отчёт по веб-конфигуратору AV Control

## Паспорт проверки

- Дата: 2026-09-21.
- Outcome: `OUT-CFG-001`.
- Pack: `0.1.0`, SHA `ceb69a957a490aeb77db0527181fec718ccd7221`.
- Продуктовый репозиторий: `C:\Cursor\IDP\av-control-configurator`.
- Фактический HEAD во время проверки: `dcef6c5e86a002fbf77470ea000d86de4f9d12e5`.
- Проверено: UI в локальном браузере, `index.html`, `assets/styles.css`, `assets/app.js`, OpenSpec/Pack, `DEL-CFG-001…005`, Evidence Bundle и release record.
- Разрушительные UI-операции удаления не выполнялись; связанные дефекты подтверждены анализом исполняемого кода.

## Вердикт

Конфигуратор не готов к выпуску. Обнаружены 8 дефектов продукта и 6 дефектов процесса/evidence. Ready gate не пройден, ряд `pass` не подтверждён, а SHA реализации расходятся между артефактами.

Синтаксическая проверка `assets/app.js` прошла. Она подтверждает только корректность синтаксиса JavaScript, но не корректность поведения.

## Методика

1. Прототип запущен через локальный HTTP-сервер.
2. Проверены библиотека, рабочее пространство, сценарии и мастер.
3. Выполнен контрольный сценарий создания и повторного открытия logic-шага.
4. Проанализированы модель состояния, удаление, валидация, версии, locks и VIS-подтверждения.
5. Сверены Pack/OpenSpec, handoff, evidence, release и Git SHA.
6. Запущены штатные validators PDE и ASE.

## Дефекты продукта

### CFG-TEST-001 — редактор существующего сценария теряет значения

- Критичность: высокая.
- Затронуто: `AC-011`.

Воспроизведение:

1. Открыть «Переговорная — корпус А» → «Сценарии».
2. Создать шаг `Громкость / Отпускание / Дисплей LG 75 / Power Off`.
3. Сохранить и повторно выбрать созданный шаг.

Фактически форма показывает `Питание / Нажатие / DSP Q-SYS Core / Toggle`, а «Удалить» остаётся disabled. Причина: обработчик вызывает `loadScenarioEditor()`, затем `renderScenariosCanvas()`, и повторная отрисовка уничтожает загруженные значения. Повторное сохранение способно незаметно изменить сценарий.

### CFG-TEST-002 — удаление сущностей оставляет висячие сценарии

- Критичность: высокая.
- Затронуто: `AC-011`, `AC-014`, `AC-015`.

`deleteDevice()`, `deleteWidget()` и `deleteScreen()` удаляют сущности и links, но не удаляют и не переназначают сценарии, которые ссылаются на их ID. Сохранённый комплект может содержать невыполнимые logic-шаги.

### CFG-TEST-003 — валидатор не проверяет сценарии

- Критичность: высокая.
- Затронуто: `AC-015`.

`validateKit()` проверяет название, экраны и links, но не существование `scenario.trigger` и `scenario.action`, допустимость команды и конфликтующие сценарии. Повреждение из `CFG-TEST-002` не появляется ни на объекте, ни в своде ошибок и не блокирует сохранение.

### CFG-TEST-004 — история версий может содержать ложные snapshots

- Критичность: высокая.
- Затронуто: `AC-023`.

`ensureVersionSnapshots()` заполняет отсутствующий исторический snapshot текущим состоянием комплекта. Несколько разных версий могут содержать одинаковый текущий снимок. Rollback уменьшает номер текущей версии, не создавая отдельную запись операции, поэтому дальнейшая история может стать неоднозначной.

### CFG-TEST-005 — блокировка двух инженеров является симуляцией

- Критичность: высокая.
- Затронуто: `AC-027`.

Lock хранится только в `localStorage`. Нет серверной атомарности, lease/heartbeat, проверки версии при записи, разрешения конфликтов и обработчика `storage` для уже открытой вкладки. Два клиента могут работать с устаревшим состоянием. `AC-027: pass` не подтверждён.

### CFG-TEST-006 — Google Fonts нарушает закрытый контур

- Критичность: средняя.
- Затронуто: `NFR-005`, `NFR-019`, `NFR-020`.

`index.html` обращается к `fonts.googleapis.com` и `fonts.gstatic.com`. Offline используется fallback, поэтому визуал не соответствует IBM Plex и зависит от наличия сети. Шрифты должны поставляться локально либо требование должно меняться через Definition Change.

### CFG-TEST-007 — UI переполняется на узком viewport

- Критичность: средняя; одновременно пробел определения.

При viewport около 687 px ширина документа составляла около 727 px: шапка обрезалась, дерево/холст/инспектор теряли читаемость, мастер накладывался на рабочую область. Единственный breakpoint скрывает метаданные и растягивает мастер, но не задаёт стратегию панелей. Pack проверяет 1440 px, но не определяет минимальную ширину и поведение ниже неё.

### CFG-TEST-008 — подтверждение VIS-CFG не является evidence

- Критичность: средняя.

Кнопка `OK` сохраняет общий флаг в `localStorage` без implementation SHA, комплекта, проверяющего, времени, браузера, viewport, скриншота и версии VIS-CFG. Старое подтверждение переносится на новую сборку или другой комплект.

## Дефекты процесса и evidence

### CFG-PROC-001 — реализация продолжена после непройденного Ready gate

- Критичность: блокирующая.

Pack содержит `outcome_state: defined`, `pack_status: draft` и blocking-вопросы `Q-001`, `Q-002`. ACK `DEL-CFG-001` имеет `needs-clarification`. Несмотря на это, появились последующие delivery, release record, Evidence Bundle и ASE → QSRE handoff.

Пропущены два барьера: PDE Ready Review и повторный `accepted` ACK в ASE.

### CFG-PROC-002 — PDE → ASE contract противоречит Pack

- Критичность: блокирующая.

`pde-to-ase.json` объявляет `pack.status: baseline`, но Pack по закреплённым repository/path/SHA содержит `pack_status: draft`. Validator проверяет структуру JSON, но не сверяет состояние с фактическим Pack.

### CFG-PROC-003 — несовместимые implementation SHA

- Критичность: блокирующая.

- Git HEAD и ASE → QSRE handoff: `dcef6c5e86a002fbf77470ea000d86de4f9d12e5`.
- `evidence.json`: `e4748ac12031d66a578070740ca13a0b8931ccec`.
- release record: `485d3b8b09acb597a7690e04fbdb9c7b945a14ff`.
- README изменён до `dcef6c5…`, но изменение не закоммичено.

Нельзя доказать, какая реализация тестировалась для каждого результата.

### CFG-PROC-004 — массовые `pass` не имеют воспроизводимых доказательств

- Критичность: блокирующая.

48 evidence-записей в основном повторяют «открыть index.html и пройти сценарий». Нет конкретных входных данных, observed result, времени, проверяющего, test run ID, скриншота или машинного отчёта. Artifact содержит только имена исходных файлов.

Исходный код доказывает наличие реализации, но не прохождение теста. Особенно недостоверны `pass` для `AC-011`, `AC-014`, `AC-023`, `AC-027` и `NFR-019`.

### CFG-PROC-005 — validators проверяют форму, но не семантику gates

- Критичность: высокая.

Штатные validators успешно приняли Pack/OpenSpec и ASE handoff, но не обнаружили:

- draft Pack при заявленном baseline;
- blocking-вопросы;
- ACK `needs-clarification`;
- конфликт implementation SHA;
- отсутствие индивидуальных evidence artifacts;
- ложные `pass`.

### CFG-PROC-006 — отсутствует обязательный тестовый контур

- Критичность: высокая.

В продуктовом репозитории нет автоматических тестов. Не покрыты edit сценария, удаления с зависимостями, dangling references, rollback/migration, две вкладки, offline, повреждённый import и граничные viewport.

## Почему это произошло

1. PDE сформировала AC/NFR без достаточных negative/recovery-сценариев для stateful и destructive-поведения.
2. Ready gate остался открытым, но contract вручную объявил Pack baseline.
3. ASE получила разрешение только на прототип, затем постепенно приравняла его к завершённой реализации без нового ACK.
4. Evidence генерировался по перечню требований и наличию исходников, а не по тестовым результатам на закреплённом SHA.
5. Validators ограничились schema и наличием полей вместо cross-repository invariants.
6. QSRE не стала обязательным барьером до заявления готовности.

## Ошибочные места процесса

### Ошибки PDE и OpenSpec

- Не заданы полные negative/recovery-сценарии create/edit/delete/import/rollback.
- Не определена referential integrity модели.
- Не определены minimum viewport и responsive-поведение.
- Не запрещены внешние runtime-зависимости для closed contour.
- Не назначен конкретный тип evidence каждому критичному AC/NFR.

### Ошибки проверки готовности PDE

- Handoff не был заблокирован при `pack_status != baseline`.
- Handoff не был заблокирован при blocking open questions.
- Contract status не сверялся с Pack по SHA.

### Ошибки среды ASE

- `needs-clarification` не остановил release-путь.
- Прототип был объявлен полной реализацией без нового ACK.
- Не создан обязательный набор автоматических тестов.

### Ошибки доказательств и передачи

- Нет единого implementation SHA.
- Исходные файлы ошибочно приняты за test evidence.
- `pass` не связан с воспроизводимым test run.

### Ошибки среды QSRE

- Критические сценарии независимо не повторены.
- Конфликт SHA и недостаточность evidence не остановили передачу.

## План исправления

1. Остановить release-путь `OUT-CFG-001`.
2. Вернуть Outcome в PDE и закрыть `Q-001`, `Q-002`.
3. Исправить противоречие `draft` / `baseline`.
4. Выпустить новый Pack SHA и новый PDE → ASE handoff.
5. Получить `accepted` ACK.
6. Исправить `CFG-TEST-001…008`.
7. Добавить тесты referential integrity, версий, concurrency, import и offline.
8. Создать Evidence Bundle заново на одном implementation SHA.
9. Передать результат в QSRE для независимого review.
10. Только после QSRE принимать решение о rollout.

## Критерии закрытия

Отчёт закрывается, когда:

- все `CFG-TEST-001…008` исправлены или приняты через Definition Change;
- Pack имеет `pack_status: baseline`;
- blocking-вопросы закрыты;
- ACK имеет `accepted`;
- один implementation SHA используется во всех артефактах;
- тесты выполнены на этом SHA;
- QSRE выпустила независимую рекомендацию;
- validators проверяют перечисленные межсредовые инварианты.
