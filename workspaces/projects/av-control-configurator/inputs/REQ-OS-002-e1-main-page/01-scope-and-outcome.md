# REQ-OS-002 · Главная страница конфигуратора (`Э-1`) — область и исход

**Change:** `chg-002-e1-main-page` (один Outcome, без Pack и `/opsx:apply` до release).  
**Родитель intake:** `REQ-OS-001-openspec-intake-rules.md` (правила APP-01…APP-15 действуют без ослабления).  
**Источники продукта:** карта экранов и `BLK-22` в функциональной структуре конфигуратора; путь `JRN-KIT-01` (шаги 1–2); `CAN-50`, `UI-01`, `UI-02`, `UI-03`; `VIS-CFG-001` (`VIS-BAN-10`, `VIS-BAN-12`); токены v0.1 §1–2, §5, §12.3.

---

## Назначение change

Зафиксировать требования OpenSpec на **UI и поведение экрана `Э-1` (библиотека комплектов)** — главной страницы веб-конфигуратора после входа инженера в уже введённый контроллер. Change не проектирует `Э-2`, мастер, деплой, админку доступа и клиент помещения.

---

## Outcome (измеримый результат)

Инженер интегратора открывает конфигуратор в браузере в закрытом контуре и **за одно действие** видит перечень комплектов контроллера, может **открыть** существующий комплект в `Э-2` или **создать** новый с явным выбором ручного режима или мастера, без маркетингового дашборда и без третьего корневого экрана (APP-06, `UI-01`/`UI-02`).

---

## Пользователь и триггер

| Поле | Значение |
| --- | --- |
| Исполнитель | инженер интегратора с правом доступа к конфигуратору (`CJM-08`, `KIT01-01`) |
| Триггер | нужно начать или продолжить подготовку комплекта (`INT-F1`, `T0` замера Time to Working Room — первое открытие конфигуратора на контроллере) |
| Предусловие | контроллер уже доступен через веб-панель; пути `JRN-ACC-01`, `JRN-SET-01` выполнены или не требуются для данного входа (`JRN-ACC-04` — сквозной вход, не часть конфигуратора) |

## Ценности (приоритет при конфликте)

| ID | Влияние на `Э-1` |
| --- | --- |
| `VAL-01` | `Э-1` сокращает путь к редактируемой основе: список + «создать» + открытие в `Э-2`; декоративный первый экран ценность не закрывает |
| `VAL-02` | На `Э-1` должны быть видны существующие комплекты для повторного открытия и тиража; одноразовый «быстрый старт» без возврата в библиотеку запрещён |
| `VAL-04` | Список комплектов и создание работают без облака и без внешней сети (`FORB-02`) |
| `VAL-05` | Узнаваемая точка входа (библиотека проектов), не копия шкурки Studio |
| `VAL-09` | Плотный служебный список, не landing |
| `VAL-12` | Без KPI-плиток, графиков и AI-chrome на домашнем экране |

При конфликте `VAL-01` и `VAL-02` побеждает `VAL-02` (APP-13).

## scope.in

- Экран `Э-1` как **единственная** точка входа в конфигуратор комплекта (`UI-01`, `CAN-50`, `KIT01-09`).
- Перечень комплектов хранилища контроллера: имя, дата изменения, признак несохранённого черновика (если есть открытая сессия), индикатор «редактируется другим источником» (`CAN-30`, `INV-7` — только отображение на уровне списка, если данные доступны).
- Действия на `Э-1`: открыть комплект → `Э-2`; создать новый комплект → черновик + выбор способа (ручной / мастер) → `Э-2` (`KIT01-10`, `CAN-08`, `CAN-03` handoff).
- Поиск по названию комплекта в библиотеке (`CAN-57` — минимум поиск; сортировка и фильтры — базовое поведение списка).
- Пустое состояние: нет ни одного комплекта (`VIS-BAN-10`).
- Визуал `Э-1` по `VIS-CFG-001` и токенам v0.1 (тёмная база, плоский акcent, без дашборда).
- Точки вызова импорта/экспорта комплекта **на уровне библиотеки** как команды, ведущие в механику `C-PRJ-3` (`BLK-27` на `Э-1`) — только кнопка/пункт и возврат на `Э-1`, без проектирования формата пакета.

## scope.out (явная передача)

| Путь / способность | Условие передачи |
| --- | --- |
| `JRN-ACC-01`, `JRN-ACC-02`, `JRN-SET-01` | До первого показа `Э-1` пользователь уже вошёл в веб-панель |
| `JRN-KIT-01` шаги 3+ | После выбора «мастер» и перехода в `Э-2` |
| `JRN-KIT-02` | После выбора «вручную» и перехода в `Э-2` |
| `JRN-COM-02`, `JRN-PNL-01` | Развёртывание и клиенты — из `Э-2` / `BLK-27`, не с домашнего дашборда |
| `JRN-MNT-01`, `CAN-06` / `US-6` | Назначение интерфейса пользователю — админка доступа `C-SEC-2`, полей «для кого» на `Э-1` нет |
| `C-PRJ-4` | Шаблоны и «готовая комната» — не третий способ на `Э-1` (`FORB-05`, `CAN-08`) |
| `JRN-DRV-02` | Получение файла драйвера — вне создания комплекта |
| Клиент помещения, `JRN-OPS-*` | `FORB-01` |
