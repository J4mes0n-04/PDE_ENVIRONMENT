# VIS-CFG-001 · Запреты визуала конфигуратора

**Читатель:** дизайнер, фронтенд, агент, собирающий макет или прототип.
**Назначение:** не допустить внешний вид «стандартного шаблона ИИ» и маркетингового SaaS на поверхности веб-конфигуратора.
**Ожидаемый результат:** макет можно отклонить по конкретному запрету, а не по вкусу.
**Граница:** документ задаёт запреты и обязательные анти-ходы для поверхности **К** (веб-конфигуратор). Он не рисует экраны. Hex акцента можно сменить в пределах стали/циана после прогона контраста; матрицу состояний менять нельзя.
**Статус:** draft. Опирается на `UI/AV Control — UI-UX принципы v0.1.md` §5, токены v0.1 и гипотезу `Q-CFG-08`.
**Поверхность:** только конфигуратор. Системное меню и стиль панели помещения сюда не входят.

**Профиль этого документа**

| Параметр | Значение |
| --- | --- |
| Нормативность | Нормативный чек-лист приёмки визуала |
| Открытые вопросы | Прогон кириллицы и контраста акцента на `#202226` (`Q-CFG-08`) |
| Обязательные разделы | Разделы 1–5 |
| Проверенное состояние | Не требуется |

Макет, прототип или сгенерированный интерфейс не принимаются, пока нарушен любой запрет со статусом **блок**.

---

## 1. Каким должен ощущаться конфигуратор

Пять прилагательных для проверки каждого визуального решения:

1. **Приборный** — как HMI/осциллограф/Q-SYS, не как стартап.
2. **Плотный** — инженер видит дерево, холст и свойства одновременно.
3. **Служебный** — статус, объект, действие. Без приветствий и слоганов.
4. **Семантический** — цвет означает состояние данных или опасность, не «живость бренда».
5. **Узнаваемый по работе** — дерево слева, инспектор справа, связь перетаскиванием. Не «та же кнопка Studio 2014».

Если решение усиливает «игрушечность», «лендинг» или «AI copilot chrome» — оно отклоняется, даже если выглядит современно.

## 3. Обязательные приёмы, без которых запреты не работают

Эти приёмы не «стиль ради стиля». Без них интерфейс снова сползает в шаблон.

1. Иерархия текста только яркостью: значение светлее подписи. Не вводить цветной текст для выразительности.
2. Выделение выбранного — один overlay на любой поверхности, не «в дереве чёрное, в меню серое».
3. Лейбл и значение в инспекторе различимы без чтения всей строки.
4. Моноширинный шрифт для технических идентификаторов, обычный — для человеческих названий.
5. Состояния полей: обычное, несохранено, ошибка, отключено — различимы без подсказки.
6. Мастер виден на фоне уже собранного комплекта. Полноэкранный wizard на белом фоне запрещён тем же основанием, что `VIS-BAN-15`.

## 4. Чек-лист приёмки макета

Перед передачей макета в разработку проверить каждый пункт. Ответ «нет» по блоку останавливает приёмку.

| Проверка | Связанный запрет |
| --- | --- |
| Нет фиолетового/индиго-градиента | `VIS-BAN-01` |
| Нет стекла и декоративных теней | `VIS-BAN-02`, `VIS-BAN-03` |
| Радиусы скромные и разные по типу, не «всё круглое» | `VIS-BAN-04` |
| Не Inter/Geist/Poppins как единственный шрифт | `VIS-BAN-05` |
| Нет стоковых иконочных кашпо и маскотов | `VIS-BAN-06`, `VIS-BAN-16` |
| На одном экране видны дерево, работа, свойства | `VIS-BAN-07` |
| Цвет только статусы и один акцент | `VIS-BAN-08` |
| Нет пружинной анимации | `VIS-BAN-09` |
| Нет маркетинговых фраз и onboarding-иллюстраций | `VIS-BAN-10` |
| Тёмная база | `VIS-BAN-11` |
| Старт — комплекты, не KPI-дашборд | `VIS-BAN-12` |
| Нет стека модалок | `VIS-BAN-13` |
| Шапка служебная | `VIS-BAN-14` |
| Мастер встроен, не карусель | `VIS-BAN-15` |
| Ошибка видна на объекте | `VIS-BAN-18` |

## 5. Рабочий стандарт MVP (`Q-CFG-08`)

**Гипотеза intake, не финальный бренд.** Для макетов и прототипов первого релиза:

- акцент `#4F8FA6` на поверхностях `#17181B` / `#202226`;
- UI — IBM Plex Sans; идентификаторы — IBM Plex Mono;
- статусы good / stale / bad / unknown;
- матрица hover / selected / focus из `UXP` §6 не пересобирается под вкус макета.

Обязательный прогон до приёмки визуала: кириллица RU/EN и контраст акцента на `#202226`. Если Plex не проходит — Source Sans 3 и JetBrains Mono. Запреты раздела 2 действуют независимо от hex: нельзя уходить в фиолетовый градиент, неоновый «AI»-зелёный или светлый admin.

---

## 6. Как применять в следующем OpenSpec-проходе

Каждый `VIS-BAN-*` со статусом блок становится кандидатом в `NFR-*` Pack. Чек-лист раздела 4 — способ проверки. Макет, прошедший чек-лист, — ожидаемое доказательство этих NFR.
