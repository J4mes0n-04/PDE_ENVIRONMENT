# Срезы поставки для ASE

Задачи не являются источником истины Pack. После Ready они могут войти в `ase-handoff.md`.

## 1. Библиотека и каркас рабочего пространства

- [ ] 1.1 Открывать конфигуратор в браузере без настольного приложения
- [ ] 1.2 Экран `Э-1`: список комплектов, создание нового, вход в существующий
- [ ] 1.3 Экран `Э-2`: дерево, холст/состав, инспектор; серверная часть и интерфейсы явно различимы
- [ ] 1.4 Сохранять границы областей между сессиями
- [ ] 1.5 Показывать несохранённые изменения по открытому комплекту
- [ ] 1.6 Блокировать сохранение без названия; разрешать неполный комплект с названием
- [ ] 1.7 Пока один правит комплект, второй только смотрит; правка после сохранения или отпуска

## 2. Ручная сборка и связи

- [ ] 2.1 Добавлять не более одной серверной части и любое число интерфейсов в любом порядке
- [ ] 2.2 Создавать связь перетаскиванием только между существующими совместимыми сущностями
- [ ] 2.3 Перед удалением связанной сущности показывать зависимости
- [ ] 2.4 Подсвечивать ошибку на элементе и вести сводный список
- [ ] 2.5 Собирать типовой сценарий без JavaScript

## 3. Мастер

- [ ] 3.1 Вызывать мастер внутри `Э-2` при создании комплекта и при добавлении устройств в открытый комплект
- [ ] 3.2 Создавать по MVP один интерфейс и класть виджеты на первую страницу
- [ ] 3.3 Принимать или корректировать предложенный состав одним действием; не записывать непринятое
- [ ] 3.4 Различать блокирующие и неблокирующие ошибки; пустую основу завершать только после явного подтверждения
- [ ] 3.5 Править результат мастера теми же командами, что и ручную сборку
- [ ] 3.7 Задавать у экрана имя и описание без поля, кому экран доступен

## 4. Гигиена, неполное железо, версия

- [ ] 4.1 Искать и удалять неиспользуемые связи, устройства, элементы и медиаресурсы без блокировки деплоя
- [ ] 4.2 Вести статусы доступно / ожидается / эмуляция и не считать «ожидается» мусором
- [ ] 4.3 Не слать команды к устройству «ожидается» на стенде
- [ ] 4.4 Сохранять новую версию используемого комплекта с возможностью отката версии

## 5. Визуал поверхности «К»

- [ ] 5.1 Применить тёмную базу, акцент `#4F8FA6`, IBM Plex Sans / Mono
- [ ] 5.2 Пройти чек-лист `VIS-BAN-01`…`VIS-BAN-18` на макетах `Э-1` и `Э-2` и на панели мастера
- [ ] 5.3 Прогнать кириллицу RU/EN и контраст акцента на `#202226` до приёмки визуала
