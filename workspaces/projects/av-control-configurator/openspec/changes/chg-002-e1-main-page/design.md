# Проектное решение

## Подход

Экран `Э-1` — библиотека комплектов, не рабочее пространство сборки. `Э-2` открывается только после явного открытия строки или после создания черновика с выбранным способом. Мастер не становится корневым экраном: после выбора «Мастер» панель мастера открывается внутри `Э-2` (`KIT01-11`, APP-06).

`BLK-22` на `Э-2` показывает расширенный состав комплекта. На `Э-1` тот же перечень сокращён до колонок MVP. Расхождение с развёрнутым членом на `Э-1` не дублируется, пока `OQ-E1-01` не решён иначе.

`BLK-27` на `Э-1` даёт только команды «Импорт» / «Экспорт». Формат пакета, диалог файла и правила переносимости остаются в `C-PRJ-3`. После вызова команды инженер возвращается на `Э-1`.

Выбор способа создания — отдельный шаг после «Создать комплект», визуально отделённый от строк перечня: модалка одного уровня только если это не разрушительное подтверждение предпочтительно заменяется inline-шагом или drawer (`VIS-BAN-13`). Третьего варианта «из шаблона комнаты» на этом шаге нет.

Черновик с временным именем не становится именованной строкой библиотеки, пока инженер не задал имя и не сохранил комплект на `Э-2`.

## Компоновка `Э-1` (гипотеза MVP)

- Сквозная боковая навигация веб-панели контроллера; конфигуратор — один из пунктов (токены §12.3). Этот change не проектирует остальные пункты меню.
- Рабочая область: служебный заголовок «Комплекты» без слогана (`VIS-BAN-14`).
- Панель инструментов: поле поиска по имени; primary «Создать комплект» высотой `control.size.default` (32px); вторичные команды импорта/экспорта, если `C-PRJ-3` доступен.
- Основная зона: таблица или список строк комплектов высотой `control.size.compact` (24px). Не менее 60% ширины основного контента занимает перечень, если есть хотя бы один комплект (`NFR-027`).
- Пустое состояние: фактический текст «комплектов нет» и действие «Создать комплект». Иллюстрация-маскот не требуется.

## Навигация

```text
[Боковое меню веб-панели] → Конфигуратор → Э-1
Э-1 → (открыть строку) → Э-2 + BLK-1
Э-1 → (создать → мастер | вручную) → Э-2
Э-2 → (закрыть комплект / библиотека через BLK-1) → Э-1
Э-1 → (импорт | экспорт) → механика C-PRJ-3 → возврат на Э-1
```

## Нефункциональные ограничения

- Фон `color.bg.canvas` `#17181B`, поверхность списка `color.bg.surface` `#202226`. Светлая тема как основная для `Э-1` запрещена (`NFR-026`, `VIS-BAN-11`).
- Подписи полей — `color.text.label`, имена комплектов — `color.text.value`.
- Плоский акцент `color.accent.default` (черновик `#4F8FA6`) только для primary «Создать комплект», рамки фокуса поиска и overlay выбранной строки `overlay.selected` `rgba(79,143,166,0.16)`.
- Запрещены фиолетовый/индиго-градиент, стекло, декоративные тени строк (`VIS-BAN-01`…`VIS-BAN-03`, `NFR-001`…`NFR-003`, `NFR-030`).
- Шрифты поставляются локально (`CAN-53`). Гипотеза MVP: IBM Plex Sans / IBM Plex Mono. Pack Ready UI `Э-1` не объявляется без прогона кириллицы RU/EN и контраста акцента на `#202226` (`FORB-03`).
- Список комплектов загружается только из хранилища контроллера. Облачный каталог и телеметрия Time to Working Room запрещены (`VAL-04`, `FORB-02`, `NFR-019`).
- На `Э-1` нет назначения экрана пользователю и нет учёток (`CAN-06`).
- Viewport 1440px: не менее 8 строк списка видны без прокрутки всего хрома страницы; внутренняя прокрутка списка разрешена (`NFR-028`).

## Зависимости и риски

- Хранилище комплектов — `C-CORE-3`. Контракт API хранилища этим change не переопределяется; `Э-1` только отображает и инициирует открытие/создание.
- Правила несохранённых изменений при возврате и смене комплекта согласуются с `AC-007` / `CAN-34` из `chg-001`. Этот change не заменяет текст `AC-007`.
- Блокировка редактирования (`INV-7`, `AC-034`) держится на сервере. На `Э-1` — только индикатор, если данные доступны.
- Импорт/экспорт зависят от готовности `C-PRJ-3`. Пока API нет, на `Э-1` нет выдуманного диалога пакета; пункт может отсутствовать.
- Удаление и переименование с `Э-1` (`OQ-E1-02`) не входят в обязательные AC, пока не подтверждены API `C-PRJ-3`.
- Остаточный риск: макет снова соберёт KPI-домашний экран. Противоядие — `NFR-027` и чек-лист `VIS-CFG-001` только для `Э-1`.

## Совместимость

- Третий корневой экран не вводится.
- Контракт `Э-2`, мастера (шаги 3+) и `wizard-change` не меняется, кроме точки входа с `Э-1`.
- `chg-001` остаётся источником требований вне `Э-1`. Для `Э-1` побеждает `chg-002`.

## Восстановление

- Ошибка загрузки списка: inline-сообщение на `Э-1` и повтор запроса к локальному хранилищу. Облачный fallback запрещён.
- Сбой создания черновика не оставляет именованную запись в библиотеке и не открывает пустой третий экран.
