# Delta for e1-kit-management

## ADDED Requirements

### Requirement: AC-009 Переименование комплекта

The system SHALL позволять инженеру переименовать комплект с `Э-1`, сохранять допустимое непустое имя в локальном хранилище и показывать новое имя после повторной загрузки перечня.

The system SHALL при пустом имени или нарушении правил хранилища не выполнять сохранение и показывать причину отказа.

#### Scenario: Успешное переименование

- **GIVEN** комплект «Зал-1» отображается на `Э-1`
- **WHEN** инженер переименовывает его в «Зал-1-новый» и подтверждает
- **THEN** после обновления списка отображается «Зал-1-новый»

#### Scenario: Отклонение недопустимого имени

- **GIVEN** инженер открыл переименование комплекта
- **WHEN** инженер подтверждает пустое имя или имя, запрещённое контрактом хранилища
- **THEN** сохранение не выполняется
- **AND** инженер видит понятную причину отказа

### Requirement: AC-010 Удаление комплекта

The system SHALL удалять комплект из локального хранилища и перечня только после явного подтверждения инженером.

При отмене подтверждения система SHALL NOT изменять хранилище и порядок строк.

#### Scenario: Подтверждённое удаление

- **GIVEN** комплект «Временный» есть в перечне
- **WHEN** инженер выбирает удаление и подтверждает
- **THEN** комплект исчезает из списка и недоступен для повторного открытия

#### Scenario: Отмена удаления

- **GIVEN** инженер инициировал удаление комплекта
- **WHEN** инженер отменяет диалог подтверждения
- **THEN** комплект остаётся в перечне на прежней позиции
