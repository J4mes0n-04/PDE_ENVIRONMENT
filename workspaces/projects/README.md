# Реальные проекты

Создавайте каждый продукт или устойчивый поток в отдельном каталоге с английским `project-id`, например `smart-building-platform`. Внутри используйте `outcomes/<outcome-id>/`.

Не размещайте реальные задачи в `workspaces/examples/`. Не размещайте нормативные документы внутри проекта: при необходимости проект добавляет локальное ограничение, которое не противоречит корневому governance.
