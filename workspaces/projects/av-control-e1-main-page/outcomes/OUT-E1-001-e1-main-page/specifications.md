# Спецификации поведения

Сценарии перенесены из утверждённого OpenSpec change. Для gates источником истины остаётся pack.json.

- Идентификатор change: chg-001-e1-main-page
- Путь change: workspaces/projects/av-control-e1-main-page/openspec/changes/chg-001-e1-main-page

## AC-006 Создание комплекта двумя способами

The system SHALL на `Э-1` предоставлять действие «Создать комплект», визуально отделённое от строк перечня. При выборе система SHALL создать черновик с временным именем, предложить ровно два способа «Мастер» и «Вручную» и после выбора открыть черновик на `Э-2`.

### Сценарий: Создать комплект через мастер

- **GIVEN** инженер находится на `Э-1`
- **WHEN** инженер выбирает «Создать комплект», затем «Мастер»
- **THEN** система открывает `Э-2` с черновиком и панелью мастера внутри рабочего пространства
- **AND** мастер не является отдельным корневым экраном

### Сценарий: Создать комплект вручную

- **GIVEN** инженер находится на `Э-1`
- **WHEN** инженер выбирает «Создать комплект», затем «Вручную»
- **THEN** система открывает `Э-2` с пустой редактируемой заготовкой
- **AND** мастер не запускается автоматически

### Сценарий: Только два способа

- **GIVEN** инженер инициировал «Создать комплект»
- **WHEN** система показывает выбор способа
- **THEN** доступны только «Мастер» и «Вручную»

## AC-007 Черновик не именованная запись

The system SHALL не создавать именованную запись комплекта в библиотеке до задания имени и явного сохранения.

### Сценарий: Черновик до сохранения

- **GIVEN** инженер создал комплект с `Э-1` и ещё не задал имя и не сохранил
- **WHEN** система показывает библиотеку или состояние черновика
- **THEN** комплект не считается именованной записью библиотеки

## AC-001 Точка входа конфигуратора

The system SHALL при открытии раздела конфигуратора комплектов авторизованным инженером за одно действие из боковой навигации показывать экран `Э-1`, а не дашборд, журнал, настройки сети, мастер как корень или иной корневой экран.

### Сценарий: Открыть библиотеку комплектов

- **GIVEN** инженер авторизован в веб-панели доступного контроллера; внешняя сеть может отсутствовать
- **WHEN** инженер выбирает раздел конфигуратора комплектов в боковой навигации
- **THEN** система открывает `Э-1`
- **AND** система показывает все локально доступные комплекты либо пустое состояние
- **AND** третьего корневого экрана сборки нет

## AC-002 Перечень комплектов

The system SHALL показывать все комплекты локального хранилища текущего контроллера плотным списком или таблицей. Для каждой строки система SHALL показывать имя, дату и время последнего сохранения. Если для комплекта есть несохранённый черновик текущей сессии, система SHALL показать индикатор в строке.

### Сценарий: Несколько комплектов

- **GIVEN** в локальном хранилище есть несколько комплектов
- **WHEN** инженер открывает `Э-1`
- **THEN** все комплекты видны в одном перечне с именами и датами последнего сохранения

### Сценарий: Несохранённый черновик сессии

- **GIVEN** для комплекта существует несохранённый черновик текущей сессии
- **WHEN** инженер смотрит строку этого комплекта на `Э-1`
- **THEN** в строке виден индикатор несохранённых изменений сессии

## AC-003 Поиск по имени

The system SHALL фильтровать перечень по подстроке имени без учёта регистра и SHALL восстанавливать полный перечень после очистки поля поиска.

### Сценарий: Фильтрация и очистка

- **GIVEN** на `Э-1` не менее трёх комплектов с разными именами
- **WHEN** инженер вводит подстроку, которая есть только в одном имени
- **THEN** перечень показывает только совпадающие комплекты
- **AND** очистка поля восстанавливает полный перечень

### Сценарий: Кириллица и регистр

- **GIVEN** в библиотеке есть комплекты с похожими именами на кириллице и латинице
- **WHEN** инженер ищет подстроку в другом регистре
- **THEN** подходящие строки остаются видимы

### Сценарий: Нет совпадений

- **GIVEN** хранилище не пусто
- **WHEN** поиск не даёт результатов
- **THEN** показывается пустой результат поиска с действием очистить запрос
- **AND** экран не выглядит как пустое хранилище

## AC-004 Сортировка списка

The system SHALL сортировать перечень по имени и по дате изменения в прямом и обратном порядке. Отдельные категориальные фильтры сверх поиска система SHALL NOT требовать в этом change.

### Сценарий: Сортировка по имени и дате

- **GIVEN** на `Э-1` несколько комплектов с разными именами и датами
- **WHEN** инженер включает сортировку по имени по возрастанию, затем по убыванию, затем по дате в обоих направлениях
- **THEN** порядок строк соответствует выбранному ключу и направлению

## AC-008 Пустое хранилище

The system SHALL при отсутствии комплектов в хранилище показывать фактическое сообщение об отсутствии комплектов и действие «Создать комплект» без онбординга, маскотов и слоганов.

### Сценарий: Первый комплект

- **GIVEN** хранилище комплектов пусто
- **WHEN** инженер открывает `Э-1`
- **THEN** перечень пуст
- **AND** видно действие «Создать комплект»

## AC-012 Локальное хранилище без облака

The system SHALL выполнять загрузку списка, поиск, сортировку, создание черновика, переименование и удаление только через локальное хранилище текущего контроллера. The system SHALL NOT обращаться к облачному каталогу комплектов и внешним сетевым сервисам для этих операций.

### Сценарий: Нет внешней сети

- **GIVEN** внешняя сеть отключена
- **WHEN** инженер открывает `Э-1`, ищет, создаёт черновик, переименовывает или удаляет комплект
- **THEN** операции завершаются без запросов к облачным каталогам и внешним сервисам

## AC-005 Открытие комплекта в Э-2

The system SHALL по явному выбору строки открывать выбранный комплект на `Э-2` и активировать контекст `BLK-1`.

### Сценарий: Найти и открыть существующий комплект

- **GIVEN** в локальном хранилище есть хотя бы один комплект
- **WHEN** инженер выбирает строку комплекта на `Э-1`
- **THEN** система открывает этот комплект на `Э-2`
- **AND** активирует контекст `BLK-1`
- **AND** инженер продолжает работу без повторного создания комплекта

## AC-009 Возврат на Э-1

The system SHALL предоставлять возврат с `Э-2` на `Э-1`. До переключения система SHALL применять существующие правила предупреждения о несохранённых изменениях (`CAN-34` / `AC-007`) и SHALL NOT переопределять их. Данные SHALL NOT теряться молча.

### Сценарий: Возврат без потерь

- **GIVEN** инженер редактирует комплект на `Э-2` с несохранёнными изменениями
- **WHEN** инженер инициирует возврат на `Э-1`
- **THEN** система применяет существующие правила предупреждения до перехода
- **AND** на `Э-1` снова виден перечень доступных комплектов

## Требования из proposal и Intent (delta-spec ожидается)

Следующие пункты зафиксированы в `proposal.md` и `pack.json`; сценарии — по Intent UC-5, UC-6 и §11 NFR.

## AC-010 Переименование комплекта

Инженер может переименовать комплект с `Э-1`; допустимое непустое имя сохраняется в локальном хранилище; пустое или недопустимое имя отклоняется с причиной.

### Сценарий: Успешное переименование

- **GIVEN** комплект отображается на `Э-1`
- **WHEN** инженер задаёт новое допустимое непустое имя и подтверждает
- **THEN** после обновления списка видно новое имя

### Сценарий: Отклонение недопустимого имени

- **WHEN** инженер подтверждает пустое или запрещённое хранилищем имя
- **THEN** сохранение не выполняется и показана причина

## AC-011 Удаление комплекта

Удаление только после явного подтверждения; отмена не меняет данные; подтверждение удаляет комплект из хранилища и списка.

### Сценарий: Подтверждённое удаление

- **WHEN** инженер подтверждает удаление
- **THEN** комплект недоступен для повторного открытия

### Сценарий: Отмена удаления

- **WHEN** инженер отменяет диалог удаления
- **THEN** комплект остаётся в перечне на прежней позиции
