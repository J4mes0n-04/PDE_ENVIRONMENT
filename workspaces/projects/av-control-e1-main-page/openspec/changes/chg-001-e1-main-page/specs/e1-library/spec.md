# Delta for e1-library

## ADDED Requirements

### Requirement: AC-002 Перечень комплектов

FR-2 · UC-1 · Intent §3, §10

The system SHALL показывать все комплекты локального хранилища текущего контроллера плотным списком или таблицей. Для каждой строки система SHALL показывать имя, дату и время последнего сохранения. Если для комплекта есть несохранённый черновик текущей сессии, система SHALL показать индикатор в строке.

The system SHALL NOT показывать на `Э-1` индикатор «редактируется другим источником».

#### Scenario: Несколько комплектов

- **GIVEN** в локальном хранилище есть несколько комплектов
- **WHEN** инженер открывает `Э-1`
- **THEN** все комплекты видны в одном перечне с именами и датами последнего сохранения

#### Scenario: Несохранённый черновик сессии

- **GIVEN** для комплекта существует несохранённый черновик текущей сессии
- **WHEN** инженер смотрит строку этого комплекта на `Э-1`
- **THEN** в строке виден индикатор несохранённых изменений сессии

### Requirement: AC-003 Поиск по имени

FR-3 · UC-2 · Intent §5, §10

The system SHALL фильтровать перечень по подстроке имени без учёта регистра и SHALL восстанавливать полный перечень после очистки поля поиска.

Пустой результат поиска SHALL отличаться от пустого хранилища: показывается отсутствие совпадений и возможность очистить запрос.

#### Scenario: Фильтрация и очистка

- **GIVEN** на `Э-1` не менее трёх комплектов с разными именами
- **WHEN** инженер вводит подстроку, которая есть только в одном имени
- **THEN** перечень показывает только совпадающие комплекты
- **AND** очистка поля восстанавливает полный перечень

#### Scenario: Кириллица и регистр

- **GIVEN** в библиотеке есть комплекты с похожими именами на кириллице и латинице
- **WHEN** инженер ищет подстроку в другом регистре
- **THEN** подходящие строки остаются видимы

#### Scenario: Нет совпадений

- **GIVEN** хранилище не пусто
- **WHEN** поиск не даёт результатов
- **THEN** показывается пустой результат поиска с действием очистить запрос
- **AND** экран не выглядит как пустое хранилище

### Requirement: AC-004 Сортировка списка

FR-4 · Intent §3, §10, допущение §12

The system SHALL сортировать перечень по имени и по дате изменения в прямом и обратном порядке. Отдельные категориальные фильтры сверх поиска система SHALL NOT требовать в этом change.

#### Scenario: Сортировка по имени и дате

- **GIVEN** на `Э-1` несколько комплектов с разными именами и датами
- **WHEN** инженер включает сортировку по имени по возрастанию, затем по убыванию, затем по дате в обоих направлениях
- **THEN** порядок строк соответствует выбранному ключу и направлению

### Requirement: AC-008 Пустое хранилище

FR-8 · Intent §5, §10

The system SHALL при отсутствии комплектов в хранилище показывать фактическое сообщение об отсутствии комплектов и действие «Создать комплект» без онбординга, маскотов и слоганов.

#### Scenario: Первый комплект

- **GIVEN** хранилище комплектов пусто
- **WHEN** инженер открывает `Э-1`
- **THEN** перечень пуст
- **AND** видно действие «Создать комплект»

### Requirement: AC-012 Локальное хранилище без облака

FR-12 · Intent §4, §10, NFR-9

The system SHALL выполнять загрузку списка, поиск, сортировку, создание черновика, переименование и удаление только через локальное хранилище текущего контроллера. The system SHALL NOT обращаться к облачному каталогу комплектов и внешним сетевым сервисам для этих операций.

#### Scenario: Нет внешней сети

- **GIVEN** внешняя сеть отключена
- **WHEN** инженер открывает `Э-1`, ищет, создаёт черновик, переименовывает или удаляет комплект
- **THEN** операции завершаются без запросов к облачным каталогам и внешним сервисам
