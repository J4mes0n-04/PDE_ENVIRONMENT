## Подтверждённые факты

- AV Control требует нескольких связанных, но различающихся поверхностей: Admin Web UI, конфигуратора, Room Client и киоск-панели.
- Admin Web UI объединяет администрирование контроллера и конфигуратор, использует общую аутентификацию и ограничивает разделы по роли.
- Клиент комнаты отображает серверное состояние и не управляет оборудованием напрямую.
- End User не должен видеть теги, драйверы, протоколы и ошибки транспорта.
- Основной комнатный сценарий запускается одним действием с главного экрана; частые действия должны укладываться в один-два шага.
- Интегратору требуются мастер, ручная доработка, preflight, preview, атомарный deploy и rollback.
- Support Operator требуются health, фильтруемые логи, triage и diagnostic bundle.
- Safe Mode оставляет Admin Web UI доступным для диагностики, restore и rollback, а Room Client показывает заглушку.
- Штатная работа не должна зависеть от интернета, облака, CDN, внешних шрифтов или внешних API.
- Ролевой доступ, TLS и аудит являются обязательными ограничениями.
- Входной документ определяет `CAP-UI-001`…`CAP-UI-020`, `AC-UI-001`…`AC-UI-025`, `NFR-UI-001`…`NFR-UI-020` и пути `JRN-UI-001`…`JRN-UI-015`.
- Риск предварительно классифицирован как `R2`, поэтому будущий Outcome потребует Full Pack.
- Числовой baseline, target и validation window основной UI-метрики не определены.
- Визуальные документы имеют статус draft/v0.1 и содержат конфликт по акцентному цвету и несколько незакрытых UX-решений.

## Предлагаемая декомпозиция

Один change на весь UI создаст слишком широкую единицу результата: он одновременно затронет проектирование, эксплуатацию комнаты, администрирование, безопасность, мониторинг и аварийное восстановление. Это затруднит измерение Outcome, независимую приёмку, rollback и передачу ASE. Инициатор принял рекомендуемое разделение на четыре change.

Рекомендуемая последовательность самостоятельных OpenSpec changes:

1. `chg-001-av-control-ui-foundation` — общая оболочка Admin Web UI, ролевая навигация, состояния, токены и базовые accessibility/offline ограничения.
2. `chg-002-av-control-configurator-ui` — мастер, ручной режим, рабочая область, preflight, preview, deploy и rollback проекта.
3. `chg-003-av-control-room-client-ui` — Room Client, kiosk, встреча, BYOD, управление и завершение сессии.
4. `chg-004-av-control-operations-ui` — health, triage, diagnostic bundle, update, backup/restore и Safe Mode.

Каждый change должен соответствовать одному будущему Outcome. Общие требования не копируются молча: первый change фиксирует foundation-контракт, остальные ссылаются на него как на зависимость.

Если владелец требует один общий Outcome, предложенный идентификатор следует заменить на `chg-001-av-control-ui`, а scope, AC/NFR, срезы и evidence станут существенно крупнее.
