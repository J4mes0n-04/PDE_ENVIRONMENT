## Целевой результат

Integrator Engineer создаёт редактируемый проект комнаты, проверяет его, смотрит preview без команд оборудованию и либо атомарно активирует сохранённую ревизию, либо видит сохранённую предыдущую рабочую версию.

## Область

Входит:

- Экран выбора мастера готовой комнаты, мастера устройств или ручного проекта
- Единое рабочее пространство с деревом, рабочей областью и инспектором
- Selection, drag-and-drop и ручная правка результата мастера
- Dirty-state, preflight, preview, атомарный deploy и rollback
- Раздельный import и export, шаблоны и политика защиты проекта
- Работа без оборудования и явно маркированный эмулятор

Не входит:

- Общая оболочка Admin Web UI, аутентификация и дизайн-токены
- Room Client, киоск, pairing и управление встречей
- Health, журналы, diagnostic bundle, обновление, backup и Safe Mode
- Внутренняя реализация Project Storage, Driver Engine и runtime
- Прямое управление оборудованием из preview
- Облачный кабинет, CDN и обязательные облачные API
- Импорт из Project Tool и криптографическая защита проекта

Оболочка входа уже описана в `OUT-UI-001`. Этот Pack начинается после входа в разрешённую поверхность конфигуратора.

## Критерии приёмки

- `AC-011` — The system SHALL предоставить Integrator Engineer два явно различимых мастер-пути: создать редактируемый проект готовой комнаты и добавить в открытый проект выбранное устройство со связанными сущностями. Доказательство: запись обоих путей и model diff созданного состава.
- `AC-012` — The system SHALL позволить Integrator Engineer создать пустую редактируемую структуру проекта и добавлять поддерживаемые сущности только явными ручными действиями. Доказательство: снимок пустого проекта и журнал явных добавлений.
- `AC-013` — The system SHALL одновременно предоставить дерево проекта, рабочую область или холст и инспектор, использующие одну ревизию проекта и один текущий selection. Доказательство: запись одной ревизии во всех трёх зонах.
- `AC-014` — The system SHALL синхронизировать selection между деревом, рабочей областью и инспектором и применять допустимый drag-and-drop как одну проверяемую мутацию модели. Доказательство: model diff одной мутации и отказ без изменения.
- `AC-015` — The system SHALL позволить вручную изменять, перемещать, связывать и удалять разрешённые сущности, созданные мастером, теми же средствами, что и сущности ручного проекта. Доказательство: правка сущности мастера теми же действиями.
- `AC-016` — The system SHALL проверять конкретную сохранённую ревизию, раздельно показывать блокеры и предупреждения и переводить пользователя к точному месту каждой проблемы. Доказательство: список блокера, предупреждения и переход к объекту.
- `AC-017` — The system SHALL построить явно обозначенный read-only preview из выбранной ревизии проекта и не отправлять из preview команды реальному оборудованию. Доказательство: признак preview, идентификатор ревизии и пустой журнал команд.
- `AC-018` — The system SHALL активировать только целиком проверенную сохранённую ревизию либо сохранить или восстановить предыдущую рабочую версию и показать фактический итог rollback. Доказательство: fault-injection deploy и подтверждённая предыдущая версия.
- `AC-019` — The system SHALL предоставить подтверждённому сервером пользователю атомарные операции раздельного import/export серверной и клиентской частей, создания и применения шаблонов и отображения действующей политики project protection. Доказательство: round-trip поддерживаемых сущностей и текст политики до действия.
- `AC-020` — The system SHALL позволить сохранять и проверять доступную часть проекта без подключённого оборудования и использовать эмулятор с однозначной маркировкой simulated-состояний. Доказательство: сохранённый проект без устройств и маркировка эмулятора.

## Нефункциональные требования

- `NFR-011` — The system SHALL сохранять согласованность проектной ревизии и явно отличать несохранённые изменения от подтверждённого сервером saved-состояния во всех заменяющих и критических операциях. Доказательство: сценарии ухода, отмены и замены с dirty-state.
- `NFR-012` — The system SHALL выполнять штатные сценарии конфигуратора через локально поставленные UI-ресурсы и доступные локальные сервисы без обязательного интернета, CDN, внешних шрифтов или облачного API. Доказательство: сетевой аудит без внешних запросов.
- `NFR-013` — The system SHALL для инженерной роли показывать локализуемый контекст ошибки и безопасное следующее действие без раскрытия секретов. Доказательство: экран ошибки без секретов и со следующим действием.
- `NFR-014` — The system SHALL на согласованном discovery-наборе сохранять сортировку, фильтрацию, grouping, читаемость, стабильный selection и клавиатурную навигацию плотных списков. Доказательство: прогон набора после его утверждения.
- `NFR-015` — The system SHALL применять project protection как серверно проверяемое ограничение обычных операций внутри AV Control и явно не представлять его криптографической гарантией. Доказательство: отказ сервера и текст без обещания шифрования.
- `NFR-016` — The system SHALL обеспечить прохождение критических путей конфигуратора с клавиатуры, видимый focus и предсказуемое восстановление focus после временных слоёв и ошибок. Доказательство: клавиатурный прогон создания, выбора, preflight и preview.

## Измерение

- Метрика: Доля критических путей конфигуратора, завершённых без помощи автора интерфейса
- Исходный уровень: Не измерен
- Цель: Не определён до discovery-среза
- Источник: Протоколы ролевых прогонов, запись экрана, model diff и журналы preflight, deploy и rollback на конкретном SHA
- Окно проверки: После выпуска пилота конфигуратора; длительность не определена
- Правило решения: scale при утверждённой цели и отсутствии стоп-сигналов; keep при подтверждении только текущего пилота; adapt при отсутствии достоверных данных; revert при потере проекта, частичном deploy, ложном rollback, облачной зависимости или команде оборудованию из preview

## План проверки

Проверить каждый AC и NFR отдельным прогоном на одном SHA: основной путь, отказ или запрет, сохранность проекта и серверный итог. Числовые пороги не закрывать до discovery.

Среды: локальный стенд конфигуратора без внешнего интернета; среда с недоступным оборудованием и отдельно запущенным эмулятором.

## Анализ угроз

Главные угрозы конфигуратора — частично активировать проект, отправить команду из preview и принять скрытие кнопки за защиту данных.

Угрозы: Deploy оставляет часть новой версии активной; Preview посылает команду реальному устройству; Прямой маршрут обходит серверный запрет; Import частично перезаписывает проект; Текст защиты обещает криптографическую гарантию.

Смягчение: Активация только всей проверенной ревизии; Preview остаётся read-only; Сервер повторно проверяет каждое действие; Import и deploy не применяются частично; Защита описана как ограничение внутри продукта.

Остаточный риск: Остаточный риск повышен, пока контракты хранения, прав и эмулятора не утверждены. Утвердил: Не назначен.
