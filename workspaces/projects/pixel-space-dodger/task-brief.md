# Тестовое задание: пиксельная игра «Космический уклон»

Document ID: BRD-PIXEL-SPACE-001  
Project: `pixel-space-dodger`  
Type: Входной тестовый документ (signal / brief)  
Status: draft  
Language: русский  
Risk hint: R0–R1 (учебный пилот, без production)

## 1. Зачем это нужно

Нужен простой, понятный тестовый продукт, чтобы проверить цепочку PDE → ASE → QSRE на реальном маленьком приложении: от краткого описания до запускаемой игры и доказательств.

## 2. Что сделать

Создать небольшое приложение, которое открывается **в отдельном окне** (не вкладка браузера как единственный целевой режим; допускается desktop-окно или отдельное окно игрового runtime).

Жанр: аркада. Игрок управляет космическим кораблём, уворачивается от астероидов и набирает очки. Корабль **стреляет автоматически**. Сложность растёт со временем (энтропия / раamping difficulty).

## 3. Игровой процесс

1. Игрок запускает приложение и видит меню.
2. Выбирает «Новая игра».
3. Корабль появляется в нижней или центральной зоне игрового поля.
4. Астероиды летят навстречу (или по полю) с нарастающей интенсивностью.
5. Корабль **сам** периодически стреляет вперёд / в сторону угрозы без ручного нажатия «огонь».
6. Попадание снаряда в астероид уничтожает астероид и даёт очки.
7. Столкновение корабля с астероидом завершает партию (game over) и предлагает вернуться в меню / начать заново.
8. Со временем растёт:
   - скорость астероидов;
   - количество одновременно присутствующих астероидов (или частота появления).

## 4. Управление (минимум)

- Движение корабля: клавиатура (рекомендуется стрелки или WASD).
- Стрельба: только автоматическая; отдельная кнопка огня не обязательна.
- В меню: выбор пунктов клавиатурой и/или мышью.

Если точная схема клавиш не зафиксирована в реализации, она должна быть описана на экране «Новая игра» или в паузе.

## 5. Графика и визуальный стиль

- Палитра: **чёрно-белая** (чёрный фон, белые или серые элементы; цвет не использовать).
- Стиль: **пиксельные квадратики** (chunky pixels / blocky sprites).
- Формы должны **отчётливо читаться**:
  - космический корабль — узнаваемый силуэт корабля (нос, корпус, возможно двигатели);
  - астероид — неровный «каменный» контур из пикселей, не путать с кораблём и выстрелом;
  - выстрел корабля — короткий яркий пиксельный снаряд / полоска;
  - фон: **движущиеся звёзды** в виде маленьких точек (параллакс или простой скролл), чтобы ощущалось движение в космосе.

## 6. Интерфейс

Обязательные элементы UI:

| Элемент | Назначение |
| --- | --- |
| Счётчик очков | Показывает текущий счёт во время игры |
| Меню «Новая игра» | Старт новой партии с нуля |
| Меню «Рекорды» | Показывает лучшие результаты (хотя бы локально на устройстве) |
| Меню «Выход» | Закрывает приложение / возвращает из игры к завершению |

Допустимо простое стартовое меню и экран game over с теми же действиями.

## 7. Рекорды

- Хранить рекорды локально (файл или local storage / аналог выбранной платформы).
- Показывать как минимум лучший счёт (top-1 достаточно для теста; top-5 желательно).
- После game over, если счёт выше рекорда, обновить таблицу.

## 8. Область работ (in scope)

- Однопользовательская игра в отдельном окне.
- Автострельба, уклонение, рост сложности, очки, меню, локальные рекорды.
- Чёрно-белая пиксельная графика с узнаваемыми спрайтами и движущимся звёздным фоном.
- Краткая инструкция управления на экране или в README приложения.

## 9. Нецели (out of scope)

- Онлайн-мультиплеер и облачные лидерборды.
- Магазин, донат, аккаунты.
- Цветная графика, 3D, сложный сюжет.
- Мобильные магазины и публикация в Steam на первом тестовом срезе.
- Звук обязателен только если останется время; для первого среза можно без звука.

## 10. Ожидаемый результат для пилота

1. Приложение запускается одной понятной командой или двойным кликом (описать в README приложения).
2. Видны меню: Новая игра / Рекорды / Выход.
3. Играбельная партия: уклон, автострельба, рост сложности, счётчик очков.
4. Рекорд сохраняется между запусками на той же машине.
5. Исходники и краткое README лежат в репозитории продукта или в каталоге Outcome после передачи в ASE.

## 11. Черновые критерии приёмки (для будущего Pack)

- **AC-001.** При запуске открывается отдельное окно с главным меню из трёх пунктов: Новая игра, Рекорды, Выход.
- **AC-002.** В партии отображается счётчик очков; уничтожение астероида выстрелом увеличивает счёт.
- **AC-003.** Корабль стреляет автоматически без ручного выстрела.
- **AC-004.** Со временем растут скорость и/или число астероидов (заметная эскалация за одну партию).
- **AC-005.** Столкновение с астероидом завершает партию и позволяет начать новую.
- **AC-006.** Экран «Рекорды» показывает сохранённый лучший результат после как минимум одной сыгранной партии.
- **AC-007.** Корабль, астероид, выстрел и звёзды визуально различимы в чёрно-белой пиксельной стилистике.
- **AC-008.** Управление кораблём осуществляется с помощью стрелок клавиатуры или аналогичных клавиш.
- **AC-009.** После завершения партии появляется экран Game Over с возможностью начать новую игру.
- **AC-010.** На экране во время игры отображается текущий счёт.
- **AC-011.** При начале новой игры счёт сбрасывается.
- **AC-012.** Позиция и скорость движения астероидов псевдослучайна, чтобы избежать одинаковых партий.
- **AC-013.** Размеры и форма астероидов варьируются (разные вариации пиксельных контуров).
- **AC-014.** Разрешён только чёрный цвет для фона и белый/серый для элементов; нет цветных объектов.
- **AC-015.** Движение звёзд фона создаёт визуальный эффект полёта (параллакс или скроллинг).
- **AC-016.** В окне меню отображается название игры.
- **AC-017.** В разделе Рекорды показывается не только лучший результат, но и таблица top-5, если есть несколько результатов.
- **AC-018.** Сохранённые рекорды хранятся локально после закрытия и перезапуска приложения.
- **AC-019.** Столкновение выстрела с астероидом уничтожает астероид и увеличивает счёт.
- **AC-020.** Корабль не должен выходить за пределы игрового окна (ограничения по краям).
- **AC-021.** Количество одновременно отображаемых выстрелов не ограничено (или реализован разумный лимит).
- **AC-022.** При игре корректно обрабатываются быстрая повторная клавиатурная навигация и нажатия.
- **AC-023.** В README или на стартовом экране есть краткие инструкции по управлению и целям игры.
- **AC-024.** Все элементы управления доступны с клавиатуры, приложение играбельно без мыши.
- **AC-025.** Код приложения лежит в отдельной папке или репозитории, готов для передачи в Outcome.
- **AC-026.** В коде и/или проекте нет внешних зависимостей, не указанных в документации.
- **AC-027.** Для тестирования предусмотрен простой режим старта (одна команда или двойной клик).
- **AC-028.** Нет критических багов, нарушающих игровую логику (корабль не застревает, очки не уходят в минус и т.п.).
- **AC-029.** Графика читается на экранах с базовым разрешением (от 800x600 и выше).
- **AC-030.** Наличие всех обязательных элементов UI: счёт, меню, рекорды, возможность выхода/перезапуска игры.

## 12. Ограничения и допущения

- Платформа реализации не зафиксирована: допустимы HTML Canvas в отдельном окне, Python/Pygame, Godot, Unity и т.п., если результат — отдельное окно и требования выше выполнены.
- Документ предназначен для тестового контура PDE; это не production-требования умных зданий.
- Pack, ASE handoff и Evidence ещё не созданы — только входной brief.
