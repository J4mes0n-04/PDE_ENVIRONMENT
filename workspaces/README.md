# Рабочие пространства

Это единственная область репозитория для конкретных продуктовых проектов и целевых результатов (Outcomes).

## Язык файлов

Все создаваемые здесь человекочитаемые документы должны быть написаны на русском языке. Имена файлов и каталогов, код, ключи JSON/YAML, устойчивые идентификаторы и служебные значения остаются на английском языке для совместимости с автоматическими проверками. Английский технический термин допустим только там, где он нужен, и должен сопровождаться понятным русским контекстом.

Граница односторонняя: платформа влияет на `workspaces/`, работа в `workspaces/` не изменяет платформу. Файлы среды из `governance/`, `architecture/`, `templates/`, `schemas/`, `scripts/`, `integrations/`, `.agents/` и соседних каталогов сюда не копируются как нормативный оригинал; шаблоны копируются в каталог результата. Создание и генерация проекта не имеют права менять файлы вне `workspaces/`. Реальная работа размещается только в `workspaces/projects/<project-id>/`.

## Каталоги

- `projects/` — реальная работа команды.
- `examples/` — демонстрационные данные, которые нельзя использовать как доказательства для промышленной эксплуатации.

## Рекомендуемая структура проекта

```text
workspaces/projects/<project-id>/
|-- README.md
|-- project-context.md
`-- outcomes/<outcome-id>/
    |-- pack.md
    |-- pack.json
    |-- decisions.md
    |-- definition-changes/
    |-- evidence.md
    |-- release-plan.md
    |-- outcome-check.md
    `-- handoffs/
```

Каждый проект определяет собственный продуктовый контекст, но наследует governance корня.

Перед созданием Outcome агент обязан изучить предоставленные работником документы и задать необходимые уточняющие вопросы по отсутствующим или неоднозначным сведениям. Итоговые файлы создаются только после ответов либо, по явному разрешению работника, как черновик с блокирующими вопросами. Каталог `outcomes/` обязателен внутри каждого проекта, а каждый результат хранится отдельно в `outcomes/<outcome-id>/`.
