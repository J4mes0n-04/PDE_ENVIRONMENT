# Контекст PDE-среды

Статус: Draft  
Назначение: архитектурное описание границ среды

## Внутри PDE-среды

- нормативные документы и их версии;
- Product Definition Pack и Definition Change;
- критерии Ready;
- templates, rules и skills PDE;
- контракты передачи в ASE и получения обратной связи из QSRE;
- Evidence Bundle index и Outcome Check;
- локальные проверки структуры и трассировки.

## Внешние системы

- GitHub хранит репозиторий, Pull Request и CI artifacts;
- Redmine хранит приоритет, состояние, assignee, сроки и ссылки;
- продуктовые репозитории хранят реализацию;
- ASE в будущем принимает проверенное определение и создаёт реализацию;
- QSRE в будущем независимо оценивает качество, безопасность и выпуск;
- Unleash управляет rollout при включении;
- OpenTelemetry и Grafana дают фактические сигналы для Outcome Check при включении;
- OpenSpace локально управляет поиском и качеством skills;
- OpenSpec локально разбирает бизнес-требования до Pack, не заменяя определение Outcome.

## Граница ответственности

PDE отвечает за качество определения и трассировку, но не подменяет продуктового владельца, реализацию ASE или независимое заключение QSRE. При отсутствии отдельных сред ASE/QSRE соответствующие функции выполняют назначенные люди, используя те же handoff-форматы.

## Данные

В Git допускаются определения, решения и ссылки на доказательства. Секреты, персональные данные, сырые журналы устройств и закрытые production traces должны оставаться в утверждённых системах; в Pack указывается ссылка и период наблюдения.
