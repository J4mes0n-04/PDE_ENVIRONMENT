# Срезы поставки для ASE

Задачи не являются источником истины Pack. После Ready они могут войти в `ase-handoff.md`. Прохождение gates определяют `pack.json` и сценарии в `specifications.md`.

Каждый пункт — одна наблюдаемая проверка. Идентификаторы ниже взяты из `specs/alerting/spec.md`.

## 1. Алерт устойчивого офлайна

После среза дежурный на рабочем месте видит один алерт, если контроллер двери остаётся офлайн дольше двух минут.

- [ ] 1.1 Исходное состояние: контроллер двери зарегистрирован и раньше был на связи, дежурный открыл рабочее место, время последнего успешного контакта известно, алерта по этому офлайну ещё нет. Без этого срез не начинается (`AC-001`).
- [ ] 1.2 Дежурный остаётся на рабочем месте, пока контакта с контроллером нет дольше двух минут, и видит один алерт по этому контроллеру (`AC-001`).
- [ ] 1.3 В появившемся алерте записаны идентификатор этого устройства и время последнего успешного контакта; других полей этот срез не требует (`AC-001`).
- [ ] 1.4 Обрыв короче двух минут с восстановлением связи не показывает на рабочем месте новый алерт устойчивого офлайна (`AC-001`).
- [ ] 1.5 Если алерт не создан, дежурный остаётся на том же рабочем месте и не видит сообщение, что контроллер остаётся недоступен (`AC-001`).
- [ ] 1.6 Запрещённый путь: смена статуса только в общем журнале, цветной дашборд, SMS или изменение прошивки не заменяют алерт на рабочем месте (`AC-001`).
- [ ] 1.7 Повторное открытие рабочего места во время того же короткого обрыва не создаёт вторую запись об устойчивом офлайне (`AC-001`).
- [ ] 1.8 После короткого обрыва идентификатор устройства и прежнее состояние рабочего места сохраняются (`AC-001`).

## 2. Состав уже показанного алерта

Срез проверяется только после того, как срез 1 показал алерт устойчивого офлайна.

- [ ] 2.1 Срез 1 уже показывает один алерт на рабочем месте дежурного. Без этого карточка полей не проверяется (`AC-002`).
- [ ] 2.2 Дежурный смотрит этот алерт и видит идентификатор устройства, которое потеряло связь (`AC-002`).
- [ ] 2.3 В том же алерте видно время последнего успешного контакта этого же устройства, а не отдельную строку журнала (`AC-002`).
- [ ] 2.4 Алерт без идентификатора или без времени последнего контакта не считается показанным: дежурный не видит такой текст как успешный алерт (`AC-002`).

## 3. Один алерт на незавершённый офлайн

- [ ] 3.1 Пока связь не восстановилась, повторная проверка того же офлайна оставляет на рабочем месте один алерт (`NFR-001`).
- [ ] 3.2 В этой карточке идентификатор устройства и время последнего успешного контакта не заменяются новой записью (`NFR-001`).
- [ ] 3.3 После ещё одной проверки числа алертов по этому офлайну остаётся один, первая карточка остаётся читаемой (`NFR-001`).

## 4. Доказательство среза

- [ ] 4.1 Для пунктов 1–3 есть прогон на одном SHA: запись проверки с датой и идентификатором `AC-001`, `AC-002` или `NFR-001`.
- [ ] 4.2 Пункт, который не удалось пройти, отмечен как непройденный и ссылается на дефект или открытый вопрос. Скрытый пропуск не закрывает срез.
