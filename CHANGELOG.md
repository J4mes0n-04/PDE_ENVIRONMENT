# Changelog

Все существенные изменения этого пакета фиксируются здесь.

## 0.1.0-draft

- Создан самостоятельный каркас PDE-среды.
- Добавлены нормативные документы, шаблоны и контракты PDE–ASE–QSRE.
- Добавлены пять PDE skills, Cursor rules и Codex configuration.
- Добавлены облегчённая JSON Schema Pack и четыре workflow GitHub Actions.
- OpenSpace подготовлен как выключенная локальная интеграция без облачного обмена.
- OpenSpec подготовлен как локальный intake перед Outcome: CLI вне `workspaces/`, рабочие файлы только в проекте, телеметрия выключена.
- Unleash, OpenTelemetry и Grafana подготовлены как выключенные опциональные интеграции.
- Демонстрационный Outcome изолирован в `workspaces/examples/`.
- Зафиксирован внешний каркас ASE: https://github.com/J4mes0n-04/ase-environment.git. QSRE как отдельная среда ещё не создана.
- Добавлены ручные межрепозиторные уведомления `notify-ase-ready` и `listen-qsre-feedback`: создаётся Issue, Pack и Pull Request не изменяются.
- Зафиксирован внешний каркас QSRE: https://github.com/J4mes0n-04/qsre-environment.git.
- Добавлены период параллельной работы и отдельный план удаления дубликатов governance без удаления файлов из PDE.
- Шаблон `templates/ase-handoff.md` расширен до рабочей передачи в разработку: сценарии, AC, NFR, ограничения, срезы, зависимости и доказательства. Контракт остаётся `1.0`.
- Шаблон `templates/specifications.md` требует подробные сценарии: исходное состояние, действие, видимый результат, краевой случай и то, что не должно произойти. Источник истины для gates по-прежнему `pack.json`.
- Шаблон `templates/openspec-change/tasks.md` требует отдельные конкретные проверки среза: действие, видимый результат, ошибка, запрещённый путь и NFR. Файл по-прежнему не заменяет Pack.
- Шаблон `templates/openspec-change/proposal.md` требует конкретные формулировки по каждому уже существующему разделу и добавляет пользователей, подтверждение, ограничения, зависимости, риски и нецели. Прежние разделы сохранены.
- Шаблон `templates/pack-full.md` разворачивает каждый обязательный раздел до наблюдаемого поведения для разработки и добавляет ограничения и границы автономии. Прежние разделы сохранены.
- Шаблон `templates/outcome-check.md` требует фактическое значение, качество данных, вторичные эффекты и одно решение `scale`, `keep`, `adapt` или `revert`. Назначение проверки результата сохранено.
- Форма `inputs/brd.md` собирает факты для OpenSpec: проблема, пользователь, результат, область, метрики, ограничения, риски и открытые вопросы. Пример фикстуры сохранён отдельно.
