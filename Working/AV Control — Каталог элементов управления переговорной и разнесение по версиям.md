# AV Control — Каталог элементов управления переговорной и разнесение по версиям

> **Статус:** draft — на согласование. **Цель:** минимальный достаточный набор элементов интерфейса управления по версиям (MVP / v1 / v2), с помощью которого интегратор соберёт панель управления малой или средней переговорной. **Метод:** систематический конкурентный аудит по скиллу `av-competitive-feature-audit` — по каждому вендору отдельный проход по официальной технической документации (tier‑1). **Дата обращения к источникам:** 2026‑07‑06.
>
> **Что покрыто (по твоему решению — оба слоя + явный список поддерживаемых шаблонов/виджетов):**
> - **Слой 1 — UI‑примитивы (палитра виджетов/шаблонов):** из чего интегратор рисует интерфейс (кнопка, слайдер, список, джойстик, видеоокно, страница и т. д.).
> - **Слой 2 — функциональные блоки управления AV:** что в переговорной можно нажать (питание, источник, громкость, камера PTZ, ВКС, свет, шторы, сценарии, бронирование и т. д.).
>
> **Профиль «малой/средней переговорной»** взят из Scope `LIM‑01` / PSD §5.2 (типовая комната: ≈1 дисплей, 1 камера/видеобар, 1 аудио‑DSP, 1 ВКС/Room PC, 1–2 BYOD, опц. коммутатор, реле/дискретные входы). PSD как отдельный файл в этой сессии не подключался — профиль взят по перекрёстным ссылкам Scope. `[?требует уточнения — путь PSD]`

## 0. Как читать документ

**Легенда покрытия у вендора:**

| Символ | Значение |
|---|---|
| ● | есть как нативный виджет/функция |
| ◐ | частично / через обходной путь (набор кнопок, кастомный виджет, плагин, устройство‑экран) |
| ○ | нет |

**Расшифровка терминов** (по правилу скилла — при первом упоминании):
- **BYOD** (bring your own device — «принеси своё устройство», подключение ноутбука/телефона пользователя к системе комнаты).
- **PTZ** (pan‑tilt‑zoom — поворот/наклон/зум управляемой камеры).
- **ВКС** — видео‑конференц‑связь (в англоязычных источниках VC / UC).
- **UCI** (User Control Interface — среда построения экранов управления в Q‑SYS).
- **MJPEG / RTSP / H.264** — форматы/протоколы видеопотока для отображения на панели.
- **CEC** (Consumer Electronics Control — управление устройствами по HDMI, типично в бытовом сегменте).
- **DSP** (digital signal processor — процессор обработки аудио).

**Колонки вендоров:** Crest — Crestron (Smart Graphics/VT Pro‑e); AMX — AMX by Harman (TPDesign5/G5, объекты G4); Extr — Extron (GUI Designer/GUI Configurator); QSC — QSC Q‑SYS (UCI); Kram — Kramer (KC Builder); C4 — Control4 (Composer); RTI — RTI (Integration Designer/APEX); HA — Home Assistant (Lovelace); oH — openHAB (Sitemap); NR — Node‑RED Dashboard; iRidi — iRidi Pro / i3 Pro (iRidium GUI Editor / studio) как внутренняя база.

**Как читать столбец «Версия»:** сопоставление предложено под архитектуру AV Control и **опирается на приоритеты Scope как на авторитет** — где у компонента карты уже есть приоритет, он и определяет версию; где решение на уровне отдельного виджета — это предложение с пометкой `[?]`. Соответствие: **MVP ↔ P0 (волны В1–В2)**, **v1 ↔ P1 (волна В3)**, **v2 ↔ P2 (волна В4)**.

**Архитектурные привязки (инварианты AV Control):**
- UI‑элемент **ВКС‑звонка** и **бронирования** — это элементы панели, которые на бэкенде работают через **драйверы слоя C** (`C-DRV` / §1.11 `C-API-1`), а не через открытый API слоя B.
- Панельный проект — это `M-ROOM` (веб‑клиент); библиотека элементов интерфейса — `C-ROOM-1`.
- «Комната» не является системной сущностью — управляемые единицы — серверный и панельный проекты; «переговорная» ниже употребляется как физическое пространство, а не как объект модели.

**Ключевые наблюдения по Слою 1:**
- **Универсальное ядро палитры** (есть у всех): кнопка, слайдер, индикатор, изображение, текст, страница/попап, навигация, группа. Это и есть неснижаемый минимум MVP.
- **Профессиональный AV‑блок** (Crestron/AMX/Extron/QSC/iRidi сильнее домашних): многосостоянийные кнопки, уровнемеры/шкалы, динамические списки, видеоокно, кейпад, звук‑по‑событию. Джойстик как отдельный виджет для PTZ — исторически сильная сторона **AMX** и **iRidi** (Joystick object); остальные делают PTZ набором кнопок.
- **Сильная сторона open source** — данные/мониторинг: график/тренд, прогресс‑бар, таблица, колорпикер (HA/openHAB/Node‑RED). Для переговорной это вторично, но пригодится в диагностических экранах.
- **Control4** — не свободный холст: интерфейс собирается из фиксированного Navigator + кнопок (Custom/Experience Buttons); произвольная палитра виджетов отсутствует — отсюда много ○.

## 3. Синтез: минимальный достаточный набор для MVP

Ниже — ответ на исходную цель: что должно быть в MVP, чтобы **интегратор собрал рабочую панель типовой переговорной** (профиль `LIM‑01`: дисплей + источник/BYOD + аудио + камера + ВКС + опц. свет по реле).

**MVP — палитра виджетов (Слой 1), 16 элементов:**
UI‑01 Кнопка · UI‑02 Триггер‑кнопка · UI‑03 «+/−» · UI‑04 Многосостоянийная кнопка · UI‑05 Индикатор/LED · UI‑06 Слайдер/уровень · UI‑09 Выпадающий список · UI‑10 Список (базовый) · UI‑11 Текст · UI‑15 Изображение · UI‑18 Страница/попап · UI‑19 Навигация/слои · UI‑25 Контейнер/группа. Плюс из блока состояний: экраны системных состояний (см. AVF‑20, частично `C-ROOM-4`). Кандидаты «на грани MVP↔v1»: **UI‑08 шкала**, **UI‑13 кейпад** (PIN/DTMF), **UI‑16 видеоокно** — зависят от решения по `C-ROOM-6` (медиа в клиенте = P2) и по DTMF в ВКС.

**MVP — функциональные блоки (Слой 2), 10 блоков:**
AVF‑01 Питание · AVF‑02 Дисплей/проектор · AVF‑04 Выбор источника · AVF‑05 Громкость/Mute · AVF‑06 Микрофон Mute · AVF‑08 Камера (базовый выбор/старт) · AVF‑10 ВКС базовый (набор/ответ/сброс/mute) · AVF‑11 Медиаплеер базовый · AVF‑12 BYOD базовый · AVF‑16 Запуск сценариев · плюс инфраструктурные **AVF‑21 Аутентификация** (P0) и минимальное освещение по реле (часть AVF‑13).

**Что осознанно уходит в v1:** камера PTZ + пресеты, аудиоматрица/зоны, мультивью, ВКС roster/раскладка/контент, диммирование/сцены света, шторы, климат, бронирование с панели (`C-ROOM-7` P1), статус/DND, многопанельная согласованность (`C-ROOM-5` P1), системные экраны состояний (`C-ROOM-4` P1/P2), а из виджетов — knob, поле ввода, кейпад, джойстик, колорпикер, часы, тост, жесты, звук‑по‑событию.

**Что уходит в v2:** видеоокно/медиапоток в клиенте (`C-ROOM-6` P2), график/тренд, веб‑виджет, прогресс‑бар, таблица, продвинутая маршрутизация/матрица и расширенная работа со сценариями с панели.

> **Разграничитель MVP:** минимальный набор сознательно опирается на **универсальное ядро палитры** (есть у всех вендоров) + **pro‑AV‑ядро комнаты** (источник/дисплей/громкость/ВКС/BYOD/сценарий). Всё, что относится к комфорту помещения (свет‑диммер/шторы/климат) и к «богатому» UX (PTZ‑джойстик, видеоокно, тренды), отложено, потому что это **объём драйверов и медиа‑стека**, а не условие «рабочей комнаты».

## 4. Отклонено (устарело / не масштабируется / конфликт с offline‑first)

| Что | Причина отклонения | Комментарий для AV Control |
|---|---|---|
| Облачный provisioning панелей/интерфейсов (iRidi Cloud, Kramer BRAINware cloud‑connections, облачные функции Crestron/Control4) | Конфликт с offline‑first и локализацией данных | Не копировать как есть; загрузка проекта и лицензирование — локально/офлайн. Региональный флаг. |
| Smart Graphics на Adobe Flash (ранние поколения Crestron) | Технологически устарело (Flash EOL) | Как ориентир по составу виджетов — да; как технология рендера — нет. |
| Фиксированный Navigator‑опыт Control4 (Watch/Listen/Comfort/Security) | Не масштабируется как свободный редактор панели (prosumer‑модель) | Полезен как набор «комнатных активностей», но не как модель произвольной кастомизации интерфейса интегратором. |
| Dashboard‑виджеты «погода/новости/RSS» (Crestron Smart Objects; погодные карточки HA/oH/NR) | Нерелевантно закрытому контуру переговорной; часто требует интернета | Вне области MVP/v1; не тащить в закрытый контур. |
| Домашние медиа‑сервисы (Sonos/Roku device pages у Control4/RTI; стриминг‑карточки HA) | Consumer‑сценарий, не переговорная | Медиаплеер в AV Control — про воспроизведение локального контента источника, не про облачный стриминг. |
| RTI/Home Assistant удалённый доступ через интернет (RTiPanel WAN, HA cloud) | Конфликт с offline‑first | Многопанельность в AV Control — в пределах локальной сети объекта. |

> Это разовый срез фильтрации, не поддерживаемый реестр. При следующем прогоне аудита — новый срез, а не патч этого.

## 5. Открытые вопросы / `[?требует уточнения]`

1. **Путь PSD** — в этой сессии PSD как отдельный файл не подключался (путь совпадал с PRD). Профиль комнаты взят из Scope `LIM‑01`. Подтвердить корректный путь либо оставить привязку к Scope.
2. **РФ‑аналоги в матрице** — добавлять ли колонку по доступным в РФ решениям (напр. Uvatron) отдельным проходом. Сейчас в матрице их нет.
3. **Граница MVP по видео в клиенте** — `C-ROOM-6` (медиа/поток) стоит P2, но базовый селф‑вью камеры / превью BYOD может требоваться уже на пилоте. Решить, поднимать ли UI‑16 (частично) в MVP.
4. **Кейпад в MVP** — нужен ли ввод DTMF/PIN уже в MVP (тогда UI‑13 → MVP), или откладываем в v1.
5. **Аппаратные элементы панели** (физические кнопки/энкодеры на панелях у входа, как у Extron TLP / Kramer) — учитывать ли их как отдельный класс «элементов управления», или каталог покрывает только экранные виджеты. Сейчас — только экранные.
6. **Версии отдельных виджетов, помеченные `[?]`** — там, где у компонента карты нет собственного приоритета, версия предложена по здравому смыслу; подтвердить или сдвинуть.
