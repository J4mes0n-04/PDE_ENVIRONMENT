### Кейсы, закрываемые вне каталога


## О документе

Справочник описывает графические элементы клиентского интерфейса панели: их назначение, закрываемые кейсы, свойства, события и состояния. Документ не является спецификацией компонента и не описывает устройство конфигуратора.

**Потребители документа:** `C-ROOM-1` (Веб-клиент управления комнатой) — поведение элементов при исполнении; `C-PRJ-5` (Кастомизация и стили клиентского интерфейса) — оформление; `C-AUT-6` (Программинг) — события, к которым привязываются действия; `C-PRJ-1` (Веб-конфигуратор и сборка проекта) — библиотека элементов как место в интерфейсе.

**Формат карточки нестрогий.** Базовый состав секций — назначение, закрываемые кейсы, свойства элемента, события, состояния, открытые вопросы, бэклог элемента. Секции, не имеющие содержания для конкретного элемента, опускаются; форма подачи выбирается по читаемости.

**Правило формулировок.** Названия свойств и событий полные и однозначные. Сокращения, требующие догадки о предмете, не допускаются.

**Открытые вопросы.** Вопросы, относящиеся к конкретному элементу, находятся в его карточке и имеют код `OQ-<ЭЛЕМЕНТ>-N`. Вопросы, общие для нескольких элементов или для всего справочника, вынесены в раздел «Сквозные открытые вопросы» с кодом `OQ-GEN-N`.

**Что в карточках не описывается:** происхождение функционала и его отличия от предыдущих продуктов; общие свойства, присущие всем элементам (геометрия, оформление, видимость); границы с другими документами — они общие для всех элементов и вынесены в раздел ниже.

# Карточки элементов

## `EL-PAGE` · Страница · MVP

**Назначение.** Основной контейнер клиентского интерфейса, служащий холстом для размещения графических элементов. Размер страницы всегда равен размеру проекта. Страница всегда находится на заднем плане относительно всех прочих элементов и не может быть скрыта — она может быть только замещена другой страницей.

**Закрываемые кейсы.** Основа любого экрана панели: экран управления комнатой, экран отдельной подсистемы (аудио, свет, климат, ВКС), экран ожидания, экран выбора сценария.

**Свойства**

|Свойство|Значения|
|---|---|
|Размер страницы|Не задаётся, всегда равен размеру проекта|
|Оформление фона страницы|Цвет заливки · изображение|

**События**

_Ввод:_ нажатие на свободную область страницы · отпускание после нажатия на свободную область страницы

Событиями ввода обрабатывается воздействие на область страницы, не занятую другими графическими элементами.

_Данные:_ открытие страницы · закрытие страницы

Открытие страницы наступает в момент, когда страница становится отображаемой. Закрытие страницы наступает в момент, когда страница замещается другой страницей.

**Состояния.** Собственных состояний не имеет.

**Открытые вопросы**

|#|Адресат|Вопрос|
|---|---|---|
|`OQ-PAGE-1`|PM|Двойное нажатие на свободную область страницы — событие справочника для программинга или способность киоск-оболочки `C-ROOM-2` при служебном входе. Кейс двойного нажатия — скрытый вход в служебный режим; иных кейсов не выявлено|
|`OQ-PAGE-2`|PM|Стартовая страница панельного проекта — свойство страницы или свойство проекта (`C-PRJ-1`). Второе исключает ситуацию с двумя стартовыми страницами|

**Бэклог элемента**

|Идея|
|---|
|Свайп по свободной области страницы в четырёх направлениях — версия 1. Требует решения `OQ-GEN-3`|
|Двойное нажатие на свободную область страницы — версия 1. Одновременная работа с одиночным нажатием требует интервала ожидания, что замедляет отклик на нажатие|
|Щипок двумя пальцами, увеличение и уменьшение. Кейса на текущем составе элементов нет: размер страницы равен размеру проекта, масштабировать нечего|

## `EL-POPUP` · Всплывающее окно · MVP

**Назначение.** Контейнер для размещения графических элементов, отображаемый поверх страницы. Существует независимо от страницы: одно и то же всплывающее окно может отображаться на разных страницах. Имеет собственный размер и положение на экране. Также используется как шаблон строки элементом `EL-LIST`.

**Закрываемые кейсы**

|Кейс|Применение|
|---|---|
|Аудио|Панель детальной настройки громкости по зонам|
|ТВ, проектор|Выбор источника сигнала|
|Камеры|Панель PTZ-управления и вызова предустановок|
|ВКС|Ввод номера или идентификатора вызова, список участников|
|Свет|Выбор световой сцены|
|Автоматизация|Подтверждение действия перед выполнением сценария|
|Навигация|Статичное меню, отображаемое одинаково на всех страницах|
|Данные|Шаблон строки для элемента `EL-LIST`|

**Свойства**

|Свойство|Значения|Волна|
|---|---|---|
|Положение всплывающего окна на экране|Координаты относительно границ проекта|MVP|
|Размер всплывающего окна|Ширина и высота; не ограничен размером страницы|MVP|
|Оформление фона всплывающего окна|Цвет заливки · изображение|MVP|
|Отображение поверх других всплывающих окон|Включено **или** выключено. При выключенном порядок наложения определяется очерёдностью открытия: позже открытое окно отображается выше ранее открытых|MVP|
|Автоматическое открытие на страницах|Не открывается автоматически · открывается на указанных страницах · открывается на всех страницах|MVP|
|Запрет взаимодействия с элементами за границами всплывающего окна|Включён **или** выключен|версия 1|
|Закрытие всплывающего окна нажатием вне его границ|Разрешено **или** запрещено|версия 1|
|Затемнение области за границами всплывающего окна|Включено **или** выключено|версия 1|

Перехват взаимодействия внутри границ всплывающего окна настройке не подлежит: воздействие на область окна никогда не доходит до элементов, расположенных под ним. Настраивается только поведение за границами окна.

Модальность отдельным свойством не описывается — она достигается сочетанием запрета взаимодействия за границами окна, затемнения области за границами и запрета закрытия нажатием вне границ.

Всплывающее окно, автоматически открываемое на нескольких страницах, при переходе между этими страницами отображается непрерывно: оно не закрывается и не открывается заново.

Автоматическое скрытие всплывающего окна по таймеру не поддерживается: задача информирования пользователя с самостоятельным закрытием закрыта элементом `EL-NOTIF`.

**События.** Собственных событий не имеет. Решение принято во избежание конфликтов с событиями страницы и событиями элементов, размещённых внутри окна.

**Состояния.** Собственных состояний не имеет.

**Открытые вопросы**

|#|Адресат|Вопрос|
|---|---|---|
|`OQ-POPUP-1`|PM|Реализация запрета взаимодействия за границами окна: отдельное независимое свойство · следствие затемнения · всегда включён · единое свойство «режим взаимодействия» с тремя значениями. Кейс статичного меню требует комбинации «не затемняет, страницу не блокирует, но собственные нажатия не пропускает»|
|`OQ-POPUP-2`|PM|Оверлей — заглушка поверх страницы при срабатывании события — заявлен в MVP, а свойства для его реализации отнесены к версии 1. Чем оверлей закрывается в MVP: страницей-заместителем или свойства возвращаются в MVP|
|`OQ-POPUP-3`|`LIM-*`|Ограничивается ли количество одновременно отображаемых всплывающих окон и что происходит при достижении предела|
|`OQ-POPUP-4`|PM|Поведение всплывающего окна, открытого пользователем вручную, при переходе на другую страницу: закрывается или остаётся отображаемым|
|`OQ-POPUP-5`|PM|Совместимость окна-шаблона со свойствами окна. Окно, используемое шаблоном строки в `EL-LIST`, не должно иметь автоматического открытия на страницах, запрета взаимодействия за границами и затемнения. Свойства игнорируются при таком использовании или окно-шаблон отмечается особо|

**Бэклог элемента**

|Идея|
|---|
|Перемещение всплывающего окна пользователем. На стационарной панели кейса нет; окно может быть уведено за край экрана|
|Эффекты появления и скрытия всплывающего окна. Анимации исключены из старта|
|Явная позиция по оси наложения, задаваемая числом. Требует ручного ведения нумерации слоёв интегратором|

## `EL-NOTIF` · Всплывающее уведомление · MVP

**Назначение.** Элемент для информирования пользователя о произошедшем событии. Не требует и не принимает действий пользователя. Отображается поверх всего содержимого экрана, не привязан к странице и закрывается самостоятельно по истечении заданной длительности. Уведомления не перекрывают друг друга даже частично.

**Закрываемые кейсы**

|Кейс|Применение|
|---|---|
|Автоматизация|Сообщение о запуске и завершении сценария|
|Все подсистемы|Сообщение об ошибке выполнения команды понятным пользователю языком|
|Все подсистемы|Сообщение о потере связи с оборудованием|
|ВКС|Сообщение о начале и завершении записи, о входящем вызове|
|Бронирование (версия 1)|Напоминание об окончании времени бронирования|

**Свойства типа уведомления**

|Свойство|Значения|
|---|---|
|Имя типа уведомления|В MVP настраивается один тип; модель допускает несколько|
|Размер уведомления|Ширина и высота|
|Длительность отображения уведомления|Время, по истечении которого уведомление закрывается самостоятельно. Отсчёт начинается с момента появления уведомления на экране, а не с момента постановки в очередь|
|Отображаемый текст уведомления|Задаётся при конфигурировании или передаётся при вызове|
|Отображаемая иконка уведомления|Задаётся при конфигурировании или передаётся при вызове|
|Оформление уведомления|Оформление фона и содержимого|

**Свойства области отображения уведомлений** — общие для всех типов, задаются один раз на панельный проект

|Свойство|Значения|
|---|---|
|Положение области отображения уведомлений на экране|Координаты относительно границ проекта|
|Направление накопления уведомлений в области|Новые снизу с вытеснением вверх · новые сверху с вытеснением вниз|
|Максимальное число одновременно отображаемых уведомлений|Число; при достижении предела остальные ожидают в очереди|
|Предел длины очереди уведомлений|Число; при переполнении отбрасываются самые ранние неотображённые|

Положение отдельного уведомления не задаётся: оно вычисляется из положения области, направления накопления и позиции уведомления в стеке. При закрытии уведомления остальные смещаются, освободившееся место занимает первое уведомление из очереди.

**События**

_Ввод:_ отсутствуют. Уведомление не принимает воздействия пользователя; воздействие на область уведомления передаётся элементам, расположенным под ним.

_Данные:_ отображение уведомления · закрытие уведомления.

**Состояния.** Собственных состояний не имеет.

## `EL-BTN` · Кнопка · MVP

**Назначение.** Основной элемент управления, отправляющий команду оборудованию по воздействию пользователя. Имеет два состояния оформления и единственное отправляемое значение. Правило, по которому меняется отображаемое состояние, задаётся отдельным свойством.

**Закрываемые кейсы**

|Кейс|Применение|
|---|---|
|Автоматизация|Запуск сценария комнаты, вызов пресета|
|Аудио|Выбор источника звука, выбор зоны|
|ТВ, проектор|Выбор источника сигнала, переключение канала|
|Камеры|Вызов предустановки положения камеры|
|ВКС|Начало и завершение вызова, ответ на входящий вызов|
|Свет|Вызов световой сцены|
|Навигация|Переход на страницу, открытие и закрытие всплывающего окна|

**Свойства**

|Свойство|Значения|
|---|---|
|Правило смены отображаемого состояния|Одно из четырёх, см. ниже|
|Отправляемое значение|Единственное; отправляется при воздействии пользователя|
|Тип отправляемого значения|Целое · дробное · строка · логический|
|Порог удержания|Длительность воздействия, после которой возникает событие удержания|
|Период повтора события удержания|Интервал, с которым событие удержания повторяется, пока воздействие продолжается|
|Оформление состояния|Задаётся отдельно для каждого из двух состояний|

**Правило смены отображаемого состояния**

|Значение|Поведение|
|---|---|
|По воздействию пользователя|Кнопка переходит во второе состояние при нажатии и возвращается в первое при отпускании. Обратная связь на отображаемое состояние не влияет|
|По повторному нажатию и обратной связи|Кнопка переходит во второе состояние при нажатии и возвращается в первое при повторном нажатии. Отображаемое состояние также меняется по значению обратной связи|
|По повторному нажатию и обратной связи с инверсией|То же, но соответствие значения обратной связи состоянию обратное|
|Не меняется|Кнопка не меняет отображаемое состояние ни при воздействии пользователя, ни при получении обратной связи|

Отправляемое значение при любом правиле одно и то же: смена отображаемого состояния не влияет на то, что отправляется. Этим кнопка отличается от триггерной кнопки, у которой каждому из двух состояний соответствует собственное отправляемое значение.

**События**

_Ввод:_ нажатие · удержание · отпускание после нажатия · отпускание после удержания

Событие удержания возникает по достижении порога удержания и далее повторяется с заданным периодом, пока воздействие продолжается. Отпускание после нажатия и отпускание после удержания взаимоисключающи: одно воздействие порождает ровно одно из этих событий.

**Состояния.** Два состояния оформления. Какое из них отображается — определяется правилом смены отображаемого состояния.

**Открытые вопросы**

|#|Адресат|Вопрос|
|---|---|---|
|`OQ-BTN-1`|PM|Правило смены отображаемого состояния — перечень из четырёх готовых правил или разложение на два независимых свойства («источник смены состояния» и «возврат состояния при отпускании»). Перечень понятнее при сборке, но не покрывает сочетание «состояние меняется по обратной связи, не реагируя на нажатие»|

## `EL-LBL` · Лейбл · MVP

**Назначение.** Элемент отображения данных. Основа для вывода текста, изображений и иконок. Не принимает воздействия пользователя и не отображает собственных состояний: воздействие на область лейбла передаётся элементам, расположенным под ним.

**Закрываемые кейсы**

|Кейс|Применение|
|---|---|
|Все подсистемы|Подпись к элементу управления или группе элементов|
|Все подсистемы|Отображение текущего значения — громкость, температура, положение камеры|
|Все подсистемы|Отображение состояния оборудования текстом, в том числе сообщения об ошибке понятным пользователю языком|
|Все подсистемы|Отображение текущего времени по системному тегу времени|
|Бронирование (версия 1)|Отображение обратного отсчёта до окончания встречи по значению таймера|
|ТВ, проектор|Отображение имени выбранного источника сигнала|
|ВКС|Отображение имени участника, длительности вызова, состояния микрофона|
|Автоматизация|Заголовки экранов и разделов интерфейса|

**Свойства**

|Свойство|Значения|
|---|---|
|Отображаемый текст|Задаётся при конфигурировании или приходит по обратной связи|
|Отображаемая иконка|Задаётся при конфигурировании или приходит по обратной связи|
|Взаимное размещение текста и иконки|Порядок и расположение относительно друг друга|
|Выравнивание содержимого по горизонтали|По левому краю · по центру · по правому краю|
|Выравнивание содержимого по вертикали|По верхнему краю · по центру · по нижнему краю|
|Поведение при нехватке места для текста|См. `OQ-LBL-1`|
|Формат отображения значения|См. `OQ-LBL-2`|
|Оформление лейбла|Оформление фона и содержимого. Применяется к содержимому целиком|

**События**

_Ввод:_ отсутствуют.

_Данные:_ изменение отображаемого содержимого.

**Состояния.** Собственных состояний не имеет.

**Разграничение с кнопкой.** Лейбл отображает, кнопка управляет. Кейсы, требующие реакции на нажатие, закрываются кнопкой — при необходимости с доработкой кнопки. Подпись, расположенная вплотную к элементу управления, не должна перехватывать касания, поэтому воздействие проходит сквозь лейбл.

**Открытые вопросы**

|#|Адресат|Вопрос|
|---|---|---|
|`OQ-LBL-1`|аналитик|**Поведение при нехватке места для текста.** Текст от оборудования непредсказуем по длине (имя источника, имя участника ВКС, текст ошибки драйвера, название сценария), а размер лейбла задан при сборке. Без явного правила вёрстка экрана ломается на реальных данных объекта, а не на тестовых. Определить: перечень допустимых способов обработки (обрезка · обрезка с многоточием · перенос по словам · автоматическое уменьшение размера шрифта до предела · прокрутка бегущей строкой), их применимость к однострочному и многострочному содержимому, поведение при нехватке места по вертикали, значение по умолчанию|
|`OQ-LBL-2`|аналитик|**Формат отображения значения.** Значение приходит от оборудования в машинном виде и в этом же виде отображается: громкость с дробной частью, температура без единицы измерения, длительность числом секунд, системное время числом. Определить: способ задания формата, состав поддерживаемых форматов (в том числе форматы даты и времени), разграничение с `C-VAR-3` — форматирование при отображении и преобразование значения при передаче суть разные задачи, лейбл не должен становиться вторым местом преобразования|
|`OQ-LBL-3`|аналитик|**Шаблоны подстановки динамических значений в текст.** Лейбл отображает одно значение; кейсы требуют большего — сообщение об ошибке из имени устройства и описания ошибки, состояние комнаты из имени сценария и времени запуска, строка бронирования из организатора, темы и времени. Определить: синтаксис шаблона, способ адресации нескольких источников в одном тексте, поведение при недоступности одного из источников, разграничение с `C-AUT-6` — подставляет ли лейбл значения сам или получает готовую строку|

**Бэклог элемента**

|Идея|
|---|
|Разметка отдельных символов внутри текста — начертание, выделение, размер для части содержимого|
|Отображение видеопотока вместо фонового изображения|
|Отображаемое содержимое при отсутствии значения — до прихода первого значения от оборудования. Связано с промежуточными состояниями элементов|

## `EL-TRG` · Триггерная кнопка · MVP

**Назначение.** Элемент с двумя взаимоисключающими состояниями. Каждое состояние имеет собственное оформление и собственное отправляемое значение. Переключение состояний — основной способ управления бинарными функциями оборудования и отображения их текущего состояния.

**Закрываемые кейсы**

|Кейс|Применение|
|---|---|
|Аудио|Mute / unmute|
|ТВ, проектор|Включение / выключение питания|
|Свет|Включение / выключение светильника или зоны|
|Климат|Включение / выключение|
|ВКС|Микрофон, камера — вкл/выкл|
|Автоматизация|Отображение состояния подсистемы без возможности управления|

**Свойства**

|Свойство|Значения|
|---|---|
|Набор состояний|Ровно два. Изменению не подлежит|
|Отправляемое значение состояния|Задаётся отдельно для каждого из двух состояний|
|Тип отправляемого значения|Целое · дробное · строка · логический|
|Правило соответствия входящего значения состоянию|Какому входящему значению соответствует каждое из двух состояний. Обратное соответствие задаётся здесь же, отдельного свойства инверсии не требуется|
|Источник смены состояния|Действие пользователя **или** обратная связь|
|Порог удержания|Длительность воздействия, после которой нажатие считается удержанием|
|Период повтора события удержания|Интервал, с которым событие удержания повторяется, пока воздействие продолжается|
|Оформление состояния|Задаётся отдельно для каждого из двух состояний|

**Источник смены состояния**

|Значение|Поведение|
|---|---|
|Действие пользователя|Элемент меняет состояние в момент воздействия пользователя. Отображаемое состояние отражает намерение пользователя, а не подтверждённое состояние оборудования|
|Обратная связь|Элемент меняет состояние только при получении значения, соответствующего одному из двух определённых состояний. Воздействие пользователя отправляет команду, но само по себе отображаемое состояние не меняет|

**События**

_Ввод:_ нажатие · удержание · отпускание после нажатия · отпускание после удержания

Отпускание после нажатия и отпускание после удержания взаимоисключающи: одно воздействие порождает ровно одно из этих событий, никогда оба.

_Данные:_ изменение состояния — текущее состояние элемента сменилось независимо от того, чем это вызвано.

**Состояния.** Два основных, условно on/off.

**Открытые вопросы**

|#|Адресат|Вопрос|
|---|---|---|
|`OQ-TRG-1`|PM|При источнике смены состояния «обратная связь» — поведение при получении значения, не соответствующего ни одному из двух определённых состояний. Отображение неопределённости потребовало бы третьего состояния, что противоречит определению элемента|
|`OQ-TRG-2`|`C-PRJ-2`|Предупреждать ли интегратора о конфигурации «источник смены состояния — обратная связь, обратная связь не настроена»: элемент никогда не изменит отображение|

**Бэклог элемента**

|Идея|
|---|
|Промежуточные состояния — ожидание, блокировка при отсутствии значения|
|Двойное нажатие как отдельное событие|

## `EL-LVL` · Уровень · MVP

**Назначение.** Задание значения в диапазоне и отображение текущего значения. Единый элемент для двух режимов работы — уровень и фейдер; фейдер отдельным элементом не является и отличается только типом шкалы.

**Закрываемые кейсы**

|Кейс|Режим|
|---|---|
|Громкость аудио|Фейдер, логарифмическая шкала|
|Диммирование света|Уровень|
|Цветовая температура света|Уровень|
|Уставка климата|Уровень|
|Zoom и focus камеры|Уровень|

**Свойства**

|Свойство|Значения|
|---|---|
|Диапазон значений|Нижняя и верхняя границы шкалы|
|Тип шкалы|Линейная **или** логарифмическая — штатно в обоих режимах работы, без привлечения дополнительного функционала|
|Шаг изменения значения|Только для линейной шкалы. Величина одного шага, постоянная на всём диапазоне|
|Кривизна шкалы|Только для логарифмической шкалы. Определяет, как величина шага меняется по диапазону|
|Ориентация шкалы|Горизонтальная · вертикальная|
|Источник смены отображаемого значения|Действие пользователя **или** обратная связь|
|Момент отправки значения|Непрерывно при движении ползунка **или** по завершении движения|
|Блокировка обратной связи при движении ползунка|Включена **или** выключена. При включённой значения обратной связи не применяются к отображению, пока пользователь ведёт ползунок; применяются после отпускания|
|Оформление частей шкалы|Задаётся отдельно для заполненной и незаполненной части шкалы|

Способ реализации типов шкалы (преобразование на элементе, на связи, иное) справочником не предписывается — определяется тех-лидом и системным аналитиком.

**События**

_Ввод:_ нажатие · движение · отпускание

Движение и отпускание независимы. Движение возникает при перемещении ползунка. Отпускание возникает при завершении воздействия пользователя независимо от того, было движение ползунка или нет.

_Данные:_ изменение значения.

**Состояния.** Два оформления шкалы — до ползунка и после ползунка. Мультистейтом не считаются.

**Открытые вопросы**

|#|Адресат|Вопрос|
|---|---|---|
|`OQ-LVL-1`|тех-лид|Момент отправки значения — настраиваемое свойство или всегда непрерывная отправка. Непрерывная отправка естественна для управления громкостью, но нагружает канал и оборудование|
|`OQ-LVL-2`|PM|Круговой уровень (`EL-LVLC`) — самостоятельная карточка или свойство «форма шкалы» у этого элемента с пометкой волны. Решается при проработке версии 1|

**Бэклог элемента**

|Идея|
|---|
|Нативное отображение шкалы — деления, разметка|
|Авто-остановка движения ползунка на заданных порогах|
|Динамическая шкала — границы диапазона задаются значением от оборудования во время работы|

## `EL-UPDN` · Кнопка вверх/вниз · MVP

**Назначение.** Элемент управления, изменяющий текущее значение на фиксированную величину при каждом воздействии пользователя. Отправляет не заранее заданное значение, а вычисленное — текущее значение плюс шаг. Элемент всегда хранит текущее значение: оно обновляется либо при собственной отправке, либо по обратной связи. Один элемент изменяет значение в одном направлении: направление задаётся знаком шага, поэтому пара «больше — меньше» собирается из двух элементов.

**Закрываемые кейсы**

|Кейс|Применение|
|---|---|
|Аудио|Пошаговое увеличение и уменьшение громкости — основной кейс элемента|
|Свет|Пошаговое диммирование|
|Климат|Изменение уставки температуры на градус|
|ТВ, проектор|Переключение канала на следующий и предыдущий|
|Камеры|Пошаговое изменение zoom и focus|

**Свойства**

|Свойство|Значения|
|---|---|
|Шаг изменения значения при нажатии|Величина, на которую изменяется значение при каждом нажатии. Положительная — значение увеличивается, отрицательная — уменьшается|
|Шаг изменения значения при удержании|Величина, на которую изменяется значение при каждом срабатывании события удержания. Задаётся отдельно от шага при нажатии|
|Предел изменения значения|Граница, за которую значение не выходит. Для положительного шага — верхняя, для отрицательного — нижняя. Предел один, поскольку элемент изменяет значение только в одну сторону|
|Значение по умолчанию|Текущее значение элемента до первого воздействия пользователя и до прихода первой обратной связи. См. `OQ-UPDN-1`|
|Порог удержания|Длительность воздействия, после которой возникает событие удержания|
|Период повтора события удержания|Интервал, с которым событие удержания повторяется, пока воздействие продолжается|
|Правило смены отображаемого состояния|По воздействию пользователя **или** не меняется|
|Оформление состояния|Задаётся отдельно для каждого из двух состояний|

**Вычисление и отправка значения.** Элемент хранит текущее значение. При воздействии пользователя вычисляется новое значение как текущее плюс соответствующий шаг; если результат не выходит за предел, он становится текущим значением и отправляется оборудованию. Изменение значения и его отправка суть одно действие — независимого счётчика у элемента нет. Текущее значение также обновляется при получении обратной связи.

Если вычисленное значение выходит за предел, действие не выполняется: значение не изменяется и не отправляется. Подрезка значения до предела не производится.

Отображение текущего значения на самом элементе не предусмотрено — эту задачу решает лейбл или уровень, размещённый рядом.

**События**

_Ввод:_ нажатие · удержание · отпускание после нажатия · отпускание после удержания

_Данные:_ изменение значения.

**Состояния.** Два состояния оформления, второе отображается только во время воздействия.

**Открытые вопросы**

|#|Адресат|Вопрос|
|---|---|---|
|`OQ-UPDN-1`|аналитик|**Значение по умолчанию.** Элемент всегда хранит текущее значение, но до первого воздействия и до первой обратной связи его неоткуда взять. Определить: задаётся ли значение по умолчанию интегратором явно, принимается ли за него предел изменения или противоположная граница, сохраняется ли текущее значение между запусками клиента|
|`OQ-UPDN-2`|аналитик|**Округление вычисленного значения.** Как поступать, если текущее значение и шаг дают дробный результат там, где оборудование принимает целое|

**Бэклог элемента**

|Идея|
|---|
|Прогрессивное ускорение: величина шага нарастает по мере удержания, вместо двух фиксированных величин|
|Отображение текущего значения на самом элементе — сейчас требует отдельного лейбла рядом|

## `EL-INPUT` · Поле ввода текста · MVP

**Назначение.** Однострочный элемент для ввода данных пользователем. Введённое значение остаётся на элементе и отправляется оборудованию или обрабатывается программингом по подтверждению ввода. По воздействию пользователя элемент получает фокус ввода и переходит в состояние ввода.

**Закрываемые кейсы**

|Кейс|Применение|
|---|---|
|ВКС|Ввод номера или идентификатора вызова|
|Все подсистемы|Ввод пин-кода для доступа к служебным функциям|
|Автоматизация|Ввод имени сценария или пресета при сохранении|
|Бронирование (версия 1)|Ввод номера комнаты, поиск по списку|

**Свойства**

|Свойство|Значения|
|---|---|
|Скрытие вводимых символов|Включено **или** выключено. При включённом вводимые символы замещаются символом-заполнителем|
|Запрет вызова системной клавиатуры при получении фокуса ввода|Включён **или** выключен. При включённом поле принимает фокус, но системная клавиатура не отображается; ввод выполняется собственной клавиатурой проекта, собранной из элементов `EL-KEY`|
|Очистка поля после отправки значения|Включена **или** выключена|
|Выравнивание содержимого по горизонтали|По левому краю · по центру · по правому краю|
|Оформление состояния|Задаётся отдельно для обычного состояния и состояния ввода|

Вызов системной клавиатуры свойством элемента не является: клавиатура вызывается действием программинга, привязанным к событию элемента. Тип вызываемой клавиатуры — полная, только цифровая, для ввода пин-кода — определяется параметром этого действия.

**События**

_Ввод:_ нажатие · отпускание · подтверждение ввода

_Данные:_ изменение введённого значения — возникает при каждом изменении содержимого поля, до его подтверждения.

**Состояния.** Два: обычное и состояние ввода. Состояние ввода отображается, пока элемент удерживает фокус ввода.

**Открытые вопросы**

|#|Адресат|Вопрос|
|---|---|---|
|`OQ-INPUT-1`|аналитик|**Момент отправки введённого значения.** На стационарной сенсорной панели физической клавиатуры нет, а системная экранная не всегда содержит клавишу подтверждения — на цифровой клавиатуре её может не быть. Определить: перечень допустимых моментов отправки (подтверждение на клавиатуре · потеря фокуса ввода · действие программинга), задаётся ли момент свойством элемента или единым правилом, поведение при уходе фокуса с неподтверждённым значением|
|`OQ-INPUT-2`|PM, `C-ROOM-1`|Поведение при перекрытии интерфейса системной клавиатурой. Актуально только при выключенном запрете вызова системной клавиатуры. Вероятный дом — поведение клиента, не свойство элемента|
|`OQ-INPUT-3`|PM|Отображение ошибки ввода: собственное состояние элемента или задача программинга с выводом в лейбл или уведомление. Собственное состояние ошибки нарушило бы модель двух состояний|
|`OQ-INPUT-4`|PM|Перевод фокуса ввода в поле по нажатию на связанную подпись. Требует связи «подпись принадлежит полю ввода»|

**Бэклог элемента**

|Идея|
|---|
|Максимальная длина вводимого значения — например, ровно четыре знака для пин-кода|
|Ограничение допустимых символов ввода — например, только цифры для номера вызова ВКС|
|Подсказка при пустом поле — текст, отображаемый, пока значение не введено|
|Маска ввода — фиксированный формат с разделителями|
|Автодополнение и подсказки при вводе на основе ранее введённых значений|
|Событие удержания. Кейса на панели не выявлено|

## `EL-KEY` · Клавиша · MVP

**Назначение.** Элемент для сборки экранной клавиатуры проекта. Отправляет символ, строку или предустановленное действие в поле ввода, удерживающее фокус. Имеет произвольное число состояний, каждому из которых соответствует собственное отправляемое содержимое и собственное оформление. Состояние меняется только по обратной связи; воздействие пользователя на состояние не влияет — это позволяет одной клавише обслуживать несколько раскладок и регистров.

**Закрываемые кейсы**

|Кейс|Применение|
|---|---|
|Все подсистемы|Ввод пин-кода собственной цифровой клавиатурой проекта|
|ВКС|Ввод номера или идентификатора вызова|
|Автоматизация|Ввод имени сценария или пресета|
|Бронирование (версия 1)|Поиск по списку помещений|

**Свойства**

|Свойство|Значения|
|---|---|
|Число состояний клавиши|От одного и более. По умолчанию одно. Задаётся при создании элемента|
|Номер текущего состояния|Приходит по обратной связи. Воздействие пользователя на состояние не влияет|
|Тип ввода|Текст с клавиши · предустановленное действие · значение по коду. Единый для всех состояний элемента|
|Отправляемое содержимое состояния|Задаётся отдельно для каждого состояния; состав определяется типом ввода|
|Реакция на воздействие|Отображается **или** не отображается|
|Оформление состояния|Задаётся отдельно для каждого состояния|

**Тип ввода**

|Значение|Отправляемое содержимое|Кейс|
|---|---|---|
|Текст с клавиши|Строка: один символ или несколько|Буквы, цифры, пробел, слово целиком|
|Предустановленное действие|Выбор из перечня: подтверждение ввода · удаление символа перед курсором · очистка поля ввода · переключение регистра|Служебные клавиши|
|Значение по коду|Числовой код символа|Символы, отсутствующие на клавиатуре|

Отправляемое содержимое задаётся отдельно от подписи клавиши: подпись — свойство оформления состояния, содержимое — свойство состояния. Это позволяет клавише пробела иметь подпись «Пробел» и вставлять пробельный символ.

**События**

_Ввод:_ нажатие · отпускание

_Данные:_ изменение состояния.

**Состояния.** Произвольное число, задаётся при создании. Каждому соответствует своё оформление и своё отправляемое содержимое.

**Открытые вопросы**

|#|Адресат|Вопрос|
|---|---|---|
|`OQ-KEY-1`|аналитик|**Механизм переключения состояний клавиатуры.** Раскладка и регистр — два независимых признака, дающие четыре комбинации при одном свойстве номера состояния. Варианты: номер состояния приходит готовым числом, вычисленным клавишами-переключателями · элемент имеет две независимые оси выбора состояния · действие программинга «установить состояние» над группой элементов. Определить также, где хранится текущая комбинация и сохраняется ли она между запусками клиента|
|`OQ-KEY-2`|аналитик|Правила изменения числа состояний после создания элемента: допускается ли уменьшение, что происходит с настройками удалённых состояний|
|`OQ-KEY-3`|`C-AUT-6`|Состав перечня предустановленных действий и разграничение с действиями программинга над полем ввода: дублируются ли они или клавиша использует те же действия|

**Бэклог элемента**

|Идея|
|---|

|Повтор ввода при удержании клавиши — удержание клавиши удаления стирает несколько символов|

## `EL-DDL` · Выпадающий список · версия 1

**Назначение.** Элемент выбора одного значения из набора. В свёрнутом виде занимает одну строку и отображает текущее выбранное значение. По воздействию пользователя раскрывается, показывая доступные значения; после выбора сворачивается и отправляет значение выбранного пункта. От списка (`EL-LIST`) отличается природой: выпадающий список имеет собственное текущее значение и отправляет его, список отображает набор данных и собственного значения не имеет.

**Закрываемые кейсы**

|Кейс|Применение|

|Аудио|Выбор входа, выбор зоны воспроизведения|

|ВКС|Выбор устройства вывода, выбор адресата вызова|
|Климат|Выбор режима работы|
|Свет|Выбор световой сцены|

**Свойства**

|Свойство|Значения|
|---|---|
|Набор значений|Перечень, задаваемый при конфигурировании|
|Состав пункта набора|Отображаемый текст и соответствующее ему отправляемое значение|
|Тип отправляемого значения|Целое · дробное · строка · логический|
|Текущее выбранное значение|Приходит по обратной связи либо устанавливается выбором пользователя|
|Отображаемое содержимое при отсутствии выбора|Текст, отображаемый, пока значение не выбрано и не пришло по обратной связи|

|Оформление пункта набора|Оформление обычного и выбранного пункта|

_Данные:_ изменение выбранного значения.

**Состояния.** Два: свёрнутое и раскрытое.

|`OQ-DDL-2`|аналитик|Поведение при получении по обратной связи значения, отсутствующего в наборе: отображать пустое значение · отображать пришедшее значение как есть · сохранять предыдущий выбор|
|`OQ-DDL-3`|PM|Поиск по набору при большом числе пунктов. Кейс — список адресатов вызова ВКС|

|Идея|

## `EL-LIST` · Список · версия 1

**Назначение.** Элемент, отображающий набор однотипных записей. Внешний вид записи задаётся всплывающим окном, выступающим в роли шаблона. Число отображаемых копий шаблона определяется числом записей в полученном наборе данных и меняется при работе без ограничений. Список настраивается под конкретную структуру данных, известную при сборке проекта.

**Закрываемые кейсы**

|Кейс|Применение|
|---|---|
|Бронирование|Список помещений с названием, статусом занятости и временем следующего события|
|Бронирование|Расписание текущего помещения на день|
|ВКС|Список участников вызова с индикацией состояния микрофона|
|ВКС|Адресная книга для исходящего вызова|
|Камеры|Список предустановок положения камеры|
|Автоматизация|Список доступных сценариев комнаты|

**Свойства**

|Свойство|Значения|
|---|---|
|Шаблон строки|Всплывающее окно, используемое как образец строки|
|Источник набора данных|Массив однотипных записей, получаемый от драйвера|
|Направление размещения копий шаблона|Вертикальное · горизонтальное|
|Интервал между копиями шаблона|Расстояние между соседними копиями|
|Отображаемое содержимое при пустом наборе|Текст, отображаемый, когда набор данных пуст|
|Оформление области списка|Оформление фона и границ|

**Модель работы.** Список получает массив записей и создаёт по копии шаблона на каждую запись. Каждая копия получает свою запись; элементы копии отображают значения этой записи. Связи элементов шаблона общие для всех копий и при копировании не размножаются: при воздействии на элемент копии в связанный тег отправляется значение записи именно этой копии.

Число копий определяется числом полученных записей и ничем не ограничивается: ни максимального числа строк, ни предварительного резервирования не предусмотрено.

Размер копии определяется размером всплывающего окна, выбранного шаблоном. Всплывающее окно, выбранное шаблоном, самостоятельно не отображается: оно существует в проекте как образец, копии отображаются только внутри списка.

Список не имеет собственной прокрутки: при содержимом, превышающем видимую область, он размещается внутри прокручиваемой области (`EL-SCROLL`).

**События**

_Ввод:_ собственных не имеет — взаимодействие происходит через элементы внутри копии шаблона.

_Данные:_ изменение состава набора данных.

**Состояния.** Собственных состояний не имеет.

**Программинг.** Действия привязываются к событиям элементов шаблона и едины для всех копий: копия, в которой произошло событие, действием не различается. Передача уникальных данных обеспечивается элементами шаблона, отправляющими значения своей записи.

**Открытые вопросы**

|#|Адресат|Вопрос|
|---|---|---|
|`OQ-LIST-1`|аналитик, тех-лид|**Сопоставление элементов шаблона со значениями записи.** Запись содержит несколько значений, шаблон — несколько элементов; требуется указание, какое значение отображает и отправляет каждый элемент. Варианты: по имени значения · по порядку значений в записи · по перечню, объявленному драйвером|
|`OQ-LIST-2`|аналитик, тех-лид|**Контракт набора данных.** Откуда и в каком виде список получает массив: формат записи, кто выполняет преобразование формата оборудования, поведение при изменении набора во время работы. Общий вопрос с динамическим набором `EL-DDL`|
|`OQ-LIST-3`|PM, `C-AUT-6`|**Различение копий в программинге.** В версии 1 действие едино для всех копий. Из шести названных кейсов четыре требуют различения: забронировать конкретное помещение, вызвать конкретную предустановку, отключить конкретного участника, позвонить конкретному адресату. Обходной путь — отправка значения записи с последующей обработкой на серверной части; определить, достаточно ли этого|

**Бэклог элемента**

|Идея|
|---|
|Различение копий в программинге — действие, относящееся к конкретной записи|
|Фильтрация и поиск по набору данных|
|Сортировка записей по значению|
|Различные шаблоны в зависимости от содержимого записи — например, выделение занятых помещений|
|Получение набора данных через преобразователь данных, а не напрямую от драйвера|
|Собственная прокрутка списка, независимая от прокручиваемой области|

# Сквозные разделы

## Сущности вне справочника

Механизмы, выявленные при проработке элементов, но не являющиеся графическими элементами. Приведены для передачи в соответствующие документы.

### Таймер

Обратный отсчёт до заданного момента и отсчёт периода бездействия — один механизм с разными настройками. Не является графическим элементом: имеет собственные события и управляется действиями программинга. Значение таймера отображается лейблом.

**Зафиксированные решения**

|Решение|Обоснование|
|---|---|
|Таймер размещается на серверной части|Время на разных панелях одного объекта не должно расходиться|
|За основу всегда берётся время серверной части|Время устройства не является источником истины|
|Момент окончания строго фиксируется сервером|Единая точка отсчёта для всех панелей|
|Сам отсчёт выполняется на клиенте|Экономия трафика: передаётся момент окончания, а не текущий остаток|

**Кейсы:** обратный отсчёт до окончания забронированной встречи · возврат панели на экран ожидания после периода бездействия · отсчёт до автоматического выключения оборудования.

**Требует проработки:** состав действий программинга (запуск, остановка, сброс), состав порождаемых событий, поведение при потере связи клиента с сервером, число одновременно работающих таймеров. Дом — `C-AUT-*`.

### Действия программинга над полем ввода

Выявлены при проработке `EL-INPUT` и `EL-KEY`. Все применяются к полю ввода, удерживающему фокус; при отсутствии фокуса не выполняются. Дом — `C-AUT-6`.

|Действие|Параметр|
|---|---|
|Вставить текст в поле ввода|Текст текущего состояния клавиши · явно заданная строка|
|Удалить символ перед курсором|—|
|Очистить поле ввода|—|
|Подтвердить ввод|—|
|Вызвать системную клавиатуру|Тип: полная · цифровая · для ввода пин-кода|

### Заготовки конфигуратора

Готовые наборы элементов, поставляемые с продуктом и используемые интегратором как основа. Дом — `C-PRJ-4`.

Выявленная потребность: цифровая клавиатура · полная клавиатура с раскладками и регистрами (по два всплывающих окна на язык). По аналогии с готовыми наборами управления камерами и ТВ. Без заготовок собственная клавиатура формально работает, но требует ручной сборки нескольких десятков клавиш на каждом объекте.

## Сквозные открытые вопросы

|#|Адресат|Вопрос|
|---|---|---|
|`OQ-GEN-1`|PM, тех-лид|**Момент отправки значения** — при нажатии или при отпускании. Отправка при нажатии даёт мгновенный отклик, отправка при отпускании позволяет пользователю передумать. Касается всех элементов, реагирующих на воздействие|
|`OQ-GEN-2`|модель событий|**Разделение события изменения по причине возникновения** — нужны ли два разных события для изменения, вызванного действием пользователя, и изменения, вызванного обратной связью|
|`OQ-GEN-3`|PM, тех-лид|**Правило перехвата жеста** — кто обрабатывает воздействие, начатое на графическом элементе: элемент или контейнер под ним. Касается страницы, прокручиваемой области и всех элементов, реагирующих на движение. Блокирует свайпы по странице и совместную работу прокрутки с уровнем внутри неё|
|`OQ-GEN-4`|PM|**Правило завершения воздействия вне границ элемента** — считается ли отпусканием завершение воздействия, если указатель уведён за границы элемента|
|`OQ-GEN-5`|`C-AUT-6`|**Механизм передачи содержимого элементу в момент его вызова.** Обычная связь работает иначе: тег меняется — элемент перерисовывается. Здесь требуется обратное: элемент появляется и должен получить актуальное содержимое на этот момент. Касается всплывающего уведомления и всплывающего окна|
|`OQ-GEN-6`|дом не определён|**Формирование текста сообщения из ответа оборудования.** Драйвер возвращает код ошибки, пользователь должен увидеть фразу. Элементы отображают готовую строку; кто её формирует, не описано ни в драйверном слое, ни в мониторинге. Без решения цель `C-ROOM-1` «говорить об ошибках человеческим языком» не достигается|
|`OQ-GEN-7`|Relations|**Привязка значения элемента и привязка отдельных свойств содержимого** (текст, иконка, цвет) — один механизм или два. Значение у элемента одно, привязок содержимого может быть несколько|
|`OQ-GEN-8`|PM|**Приоритет кейса бронирования** — MVP или версия 1. Определяет волну списка и выпадающего списка|
|`OQ-GEN-9`|`C-VAR-*`|**Состав системных тегов времени.** Требуется ли отдельный тег на каждый формат отображения или один тег со значением, форматируемым при отображении. Связано с `OQ-LBL-2`|
|`OQ-GEN-10`|тех-лид, `C-ROOM-1`|**Отрисовка большого числа элементов.** Список не имеет продуктового предела числа копий шаблона; несколько сотен копий на панели невысокой мощности — вопрос производительности клиента, а не продуктового ограничения|

## Закрытые вопросы

| Вопрос                                                          | Решение                                                                                                                       |
| --------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| Порог удержания — свойство элемента или общая настройка проекта | Свойство элемента. Длительность удержания для служебной кнопки и для кнопки шага громкости различается по смыслу              |
| Автоматическое скрытие всплывающего окна по таймеру             | Не поддерживается. Задача закрыта элементом `EL-NOTIF`. Открывается заново при появлении кейса временной интерактивной панели |
| Защита нажатия паролем                                          | Прорабатывается отдельно вне справочника. Затрагивает `C-SEC-2` и `C-ROOM-3`, пересекается с `C-PRJ-1/US-35`                  |
| Инверсия обратной связи как отдельный режим у триггерной кнопки | Не требуется: обратное соответствие задаётся свойством «правило соответствия входящего значения состоянию»                    |
| Повтор события удержания                                        | Перенесён из бэклога в свойства кнопки и триггерной кнопки                                                                    |
| Лейбл принимает воздействие пользователя                        | Не принимает. Кейсы с реакцией на нажатие закрываются кнопкой                                                                 |
| Поведение кнопки вверх/вниз без обратной связи                  | Вопрос снят: элемент всегда хранит текущее значение, обратная связь — лишь один из двух источников его обновления             |
| Выбор типа системной клавиатуры как свойство поля ввода         | Не свойство элемента: клавиатура вызывается действием программинга с параметром типа                                          |
| Virtual key как отдельный элемент                               | Переосмыслен и сохранён под кодом `EL-KEY`. Мультистейт допущен как исключение — только для этого элемента                    |
| Тип ввода клавиши — свойство элемента или состояния             | Свойство элемента, единое для всех состояний. Кейс смешанной клавиши не выявлен                                               |
| Часы как отдельный элемент                                      | Исключены. Текущее время отображается лейблом, связанным с системным тегом времени                                            |
| Выпадающий список и список — один элемент или два               | Два самостоятельных элемента. Выпадающий список имеет собственное текущее значение и отправляет его, список — нет             |
| <br><br><br><br>Прокрутка как свойство списка                   | Вынесена в отдельный элемент `EL-SCROLL`. Кейс меню, не помещающегося в экран, к данным отношения не имеет                    |
