Смотрел на актуальность: список ниже проверен через поиск на 2026 год — все системы активно поддерживаются сейчас (в т.ч. со свежими версиями/апдейтами в 2026), не архивные. Google Material и Apple HIG сознательно не включаю в саму подборку — вы упомянули их как эталон _качества документации_, но по стилю они консьюмерские/дружелюбные, а не для инженерной аудитории; ниже — системы, которые одновременно хорошо задокументированы и по духу корпоративно-промышленные.

## 1. Siemens iX (Siemens Industrial Experience)
Прямое попадание в бриф: буквально design system "для промышленных программных продуктов" от промышленного гиганта — open-source, 500+ инженерных иконок, актуальная версия (v3–v4) в 2026, есть даже MCP-сервер для AI-агентов (`@siemens/ix-mcp`) — можно скормить прямо в промт. Гайдлайн: **ix.siemens.io**, репозиторий — **github.com/siemens/ix**.

## 2. IBM Carbon Design System
Плотная, enterprise-grade система для сложных data-heavy продуктов. Важная деталь под вашу проблему из брейншторма про "неоднозначный статус кнопки": у Carbon иерархия и глубина (elevation) в тёмной теме выражаются **цветом поверхности, а не тенью** — то есть у них уже решена ровно та задача, которую вы описывали как боль в Studio. Открытый исходный код, зрелая документация, компоненты для Figma. Гайдлайн: **carbondesignsystem.com**.

## 3. Microsoft Fluent 2
Актуальная версия (Fluent 2, не устаревший Fluent 1/Metro), используется в профессиональных инструментах вроде Power BI и Azure Portal — то есть уже проверена на плотных, конфигурационных интерфейсах, а не только на консьюмерских. Даёт готовые токены (цвет, отступы, elevation, радиусы, толщина обводки) и явный принцип "adopt principles before visuals" — совпадает с процессом деконструкции референсов, который мы обсуждали. Гайдлайн: **fluent2.microsoft.design**.

## 4. GitHub Primer
Единственная в списке система, изначально построенная под аудиторию именно **разработчиков/инженеров**, не бизнес-пользователей — сдержанная, тёмная тема продумана как первоклассная (а не докрученная поверх светлой), собственная иконочная система (Octicons). Хороший референс именно для "К" (веб-конфигуратор) — по духу ближе всего к VS Code, который мы уже упоминали. Гайдлайн: **primer.style**.

## 5. SAP Fiori
Из всего списка — самая близкая по природе продукта к вашему: ERP-класс, экстремально высокая информационная плотность, аудитория — операторы и инженеры сложных корпоративных систем, а не конечные потребители. Полезна прицельно как референс для деревьев/списков/таблиц из вашего §3 (UXP-14). Гайдлайн: **experience.sap.com/fiori-design**.

## Честная оговорка про одну систему, которую НЕ рекомендую как основу

**Ant Design** (Alibaba) технически подходит по всем формальным критериям — минималистичная, корпоративная, отлично задокументирована, огромное количество примеров. Но именно из-за огромной популярности она стала визуальным штампом почти всех B2B/dashboard-продуктов последних лет — тот самый риск "видно, что сделано по шаблону", только не AI-шаблон, а Ant-шаблон. Если где-то и смотреть на неё — то на структурные решения (как устроены плотные таблицы, фильтры), не на внешний вид.

## Как этим пользоваться дальше

Ровно по процессу из §4 предыдущего документа: не копировать полностью одну систему, а из каждой вытащить 1-2 принципа. По первому впечатлению уже видно направление: **Siemens iX** — по духу продукта ближе всего (буквально "industrial"), **Carbon** — по решению проблемы состояний/иерархии без теней, **Primer** — по тону для инженерной аудитории, **Fiori** — по плотности данных, **Fluent 2** — по токен-архитектуре как образцу структуры документа.

Пишите свой список идей — когда будет готов, сведём его с этими референсами в конкретные токены и оттуда в промт.
