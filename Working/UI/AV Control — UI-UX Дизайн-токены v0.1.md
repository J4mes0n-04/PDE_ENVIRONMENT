# AV Control — Дизайн-токены веб-интерфейса контроллера (черновик v0.1)

> **Статус.** Черновик, первая фиксация конкретных значений. Формат рассчитан на двойное чтение — дизайнером и AI-агентом (может быть скормлен напрямую в промт генерации прототипа).
>
> **Область.** Единое веб-приложение контроллера: конфигурация сети/системы, дашборд мониторинга, логи и отладка, веб-конфигуратор проектов (серверный + панельный). Далее по тексту — «веб-интерфейс контроллера». Дефолтный стиль элементов клиентской панели (поверхность «П» из принципов) сюда не входит — недостаточно материала для токенов, прорабатывается отдельно.
>
> **Источники.** (1) Легаси iRidi Studio (Qt) — известный пользователям паттерн, наследуем поведение, не техническую реализацию. (2) OpenAVC — единственный референс, изученный вживую: перенимаем цветовую конвенцию лейбл/значение и сворачиваемую боковую панель; не перенимаем разрозненные деревья по страницам и непостоянную шапку. (3) Figma — принцип единого окна без переключений между попапами. (4) Индустриальные дизайн-системы, разобранные ранее (Carbon, Siemens iX, Fluent 2, Primer, Fiori) — как основа для конкретных технических решений (elevation через цвет, а не тень; overlay-состояния).
>
> **Формат имён.** Точечная нотация (`category.subcategory.variant`) — переносится в CSS custom properties напрямую (`--color-bg-canvas` и т.п.), удобна и для чтения, и для промта.

## 1. Цвет

### 1.1 Нейтральная база (тёмная тема)

| Токен | Значение (черновое) | Назначение |
|---|---|---|
| `color.bg.canvas` | `#17181B` | Базовый фон приложения — самый тёмный слой |
| `color.bg.surface` | `#202226` | Поверхность блока (дерево, инспектор, тулбар) — на шаг светлее канваса |
| `color.bg.surface-raised` | `#2A2D32` | Приподнятая поверхность: дропдаун, попап, контекстное меню |
| `color.bg.sunken` | `#141518` | «Утопленная» поверхность: поля ввода, область холста |
| `color.border.subtle` | `#2A2D31` | Разделители внутри блока (строки дерева, пункты меню) |
| `color.border.default` | `#383B41` | Границы блоков, полей, панелей |
| `color.border.strong` | `#4A4E56` | Только по семантике (см. §1.4 focus), не декоративно |

Иерархия глубины (canvas → surface → surface-raised) задаётся **изменением тона, не тенью** — так же решено в Carbon: экономит один визуальный ресурс (тень) для более важной задачи — сигналов состояния.

### 1.2 Текст: лейбл/значение

Прямое требование из референсов (Studio + OpenAVC совпадают):

| Токен | Значение | Назначение |
|---|---|---|
| `color.text.value` | `#F2F3F5` | Значения полей, основной интерактивный текст — самый светлый |
| `color.text.label` | `#8A8F98` | Подписи полей, названия свойств — тёмно-серый |
| `color.text.muted` | `#63676E` | Второстепенный текст: подсказки, счётчики использования, неактивные ветки |
| `color.text.disabled` | `#484B50` | Текст заблокированных элементов |

Правило: **эта иерархия яркости — единственный способ показать важность текста**. Не вводим дополнительных цветов текста ради выразительности — только эти четыре уровня, везде.

### 1.3 Акцент (единственный несемантический цвет)

`[?требует уточнения — пересмотрено относительно раннего предложения]` Ранее я предлагал приглушённый медно-янтарный акцент как анти-generic-AI решение. При полноценной палитре статусов (см. §1.4) это создаёт ровно ту путаницу, которую вы просите исключить — тёплый жёлто-коричневый акцент визуально спорит с «предупреждением/устаревшими данными». Предлагаю сместить акцент в сине-стальной/циановый диапазон — вне зоны красный/жёлтый/зелёный, читается как «техническое приборное» (осциллограф, HMI), не как дефолтный SaaS-градиент индиго-фиолетового:

| Токен | Значение | Назначение |
|---|---|---|
| `color.accent.default` | `#4F8FA6` | Активная навигация, выбранная вкладка, primary-кнопка, фокус |
| `color.accent.hover` | `#5FA1B9` | Наведение на акцентный элемент |
| `color.accent.pressed` | `#437B90` | Момент нажатия |

### 1.4 Семантика состояний и статусов — единая палитра

Это прямой ответ на вашу проблему «активно» с разным цветом в разных меню. Решение: **состояния кодируются не отдельными цветами фона, а overlay (полупрозрачным наложением) поверх любой базовой поверхности** — тогда «выбрано» выглядит одинаково и на канвасе, и в дереве, и в списке, независимо от того, какой у них базовый тон.

| Токен | Значение | Применение |
|---|---|---|
| `overlay.hover` | `rgba(255,255,255,0.06)` | Наведение курсора на любой интерактивный элемент |
| `overlay.pressed` | `rgba(255,255,255,0.10)` | Момент нажатия |
| `overlay.selected` | `rgba(79,143,166,0.16)` (на основе `accent.default`) | Выбранный элемент — дерево, список, вкладка, пункт меню. Один и тот же расчёт везде — устраняет проблему «в одном месте чёрное, в другом серое» |

Статусные цвета (данные/качество, из модели `good/stale/bad/unknown`, и severity `info/warn/error/critical`) — единственные дополнительные цвета в системе, кроме акцента:

| Токен | Значение | Назначение |
|---|---|---|
| `color.status.good` | `#4FA876` | Данные актуальны / успех |
| `color.status.stale` | `#C4A24E` | Данные устарели (жёлто-охристый — сознательно дальше от акцента и от error) |
| `color.status.bad` | `#D66B63` | Ошибка данных / связи |
| `color.status.unknown` | `#63676E` (= `color.text.muted`) | Нет данных — не цвет, а нейтральный серый, чтобы не плодить лишний оттенок |
| `color.severity.info` | `= color.accent.default` | Информационное уведомление — переиспользуем акцент, не вводим пятый цвет |
| `color.severity.warn` | `= color.status.stale` | Предупреждение |
| `color.severity.error` | `= color.status.bad` | Ошибка |
| `color.severity.critical` | `#E8433A` | Критическая ошибка — единственный цвет ярче error, зарезервирован только для блокирующих ситуаций |

Итого палитра — **6 хроматических значений на весь продукт** (1 акцент + 4 статуса + 1 critical), остальное — оттенки серого. Это и есть «минимум цветов» из вашего требования, переведённый в конкретику.

## 2. Типографика

**Требование RU+EN.** Кириллица обычно длиннее латиницы на 15–20% при том же смысле — учитываем в горизонтальных отступах контролов с текстом (см. §5), не только в выборе шрифта.

`[?требует уточнения — гарнитура не финализирована]` Предложение: **IBM Plex Sans** для интерфейса (полная поддержка кириллицы, технический некорпоративно-глянцевый характер, разработан для enterprise-контекста — та же логическая линия, что и референс Carbon) + **IBM Plex Mono** для ID/тегов/IP-адресов/логов. Альтернатива для моно — JetBrains Mono. Не Inter/Geist — сознательно, чтобы не попасть в «дефолтный AI-стартап» шрифтовой почерк.

| Токен | Значение | Назначение |
|---|---|---|
| `type.family.ui` | IBM Plex Sans | Весь интерфейсный текст |
| `type.family.mono` | IBM Plex Mono | ID, теги, IP/MAC-адреса, значения в логах, версии |
| `type.size.xs` | 11px | Счётчики использования, микро-метки |
| `type.size.sm` | 12px | Лейблы, второстепенный текст, вложенные уровни дерева |
| `type.size.base` | 13px | Основной UI-текст: значения полей, пункты меню, строки дерева |
| `type.size.md` | 14px | Заголовки блоков, активные пункты навигации |
| `type.size.lg` | 16px | Заголовки экранов/разделов (используется редко) |
| `type.weight.regular` | 400 | Значения, обычный текст |
| `type.weight.medium` | 500 | Лейблы активных состояний, заголовки блоков |
| `type.weight.bold` | 700 | Зарезервирован для критических предупреждений — не для декоративного акцента |

## 3. Отступы

Шкала на основе 4px — устойчивый выбор enterprise-систем (тот же принцип у Carbon):

| Токен | Значение |
|---|---|
| `space.xxs` | 2px |
| `space.xs` | 4px |
| `space.sm` | 8px |
| `space.md` | 12px |
| `space.lg` | 16px |
| `space.xl` | 24px |
| `space.xxl` | 32px |

Правило: внутри одного блока/группы используется **один шаг шкалы**, не смешиваем — это и есть техническое воплощение «отступы должны быть выверены».

## 4. Радиусы

Минимализм — не «скруглить всё», а осознанно почти не скруглять:

| Токен | Значение | Применение |
|---|---|---|
| `radius.none` | 0 | Строки дерева/списка — должны визуально сливаться в непрерывную структуру, не в отдельные «карточки» |
| `radius.sm` | 2px | Поля ввода, кнопки, чекбоксы |
| `radius.md` | 4px | Панели, всплывающие меню, модальные окна |

## 5. Размерные группы контролов

Прямой ответ на требование «элементы одной группы строго единообразны по размеру»:

| Токен | Высота | Где используется |
|---|---|---|
| `control.size.compact` | 24px | Строки дерева, строки списка, плотные тулбары |
| `control.size.default` | 32px | Стандартные кнопки, поля ввода, триггеры дропдаунов |
| `control.size.large` | 40px | Первичные действия — редко, например подтверждение в модалке |

Правило: в рамках одного контекста (дерево, тулбар, инспектор) — один уровень, без смешения. Горизонтальные отступы внутри контролов с текстом — на `space.sm`–`space.md` больше номинально нужного, с запасом под кириллицу (см. §2).

**Минимальная кликабельная зона** (не зум браузера — вариативность физического разрешения экрана): `hit.min-target = 24×24px` даже для иконки внутри `control.size.compact`; `hit.min-gap = 4px` минимум между соседними кликабельными элементами — снижает риск мисклика без раздувания интерфейса.

## 6. Состояния интерактивных элементов — единая матрица

Применяется ко всем элементам без исключения (кнопка, пункт дерева, вкладка, пункт меню):

| Состояние | Визуальное решение |
|---|---|
| Default | Базовый `color.bg.*` + `color.border.default` |
| Hover | + `overlay.hover` (обязательно для всех интерактивных элементов — прямое требование) |
| Pressed | + `overlay.pressed` |
| Selected/Active | + `overlay.selected`, одинаково во всех контекстах |
| Focus (клавиатурная навигация) | Обводка `color.border.strong` в 1–2px, всегда видима — единственное легитимное применение `border.strong` |
| Disabled | `color.text.disabled` + без hover/pressed-реакции + курсор `not-allowed` |

## 7. Иконки — иконка определяет поведение

Три однозначных маркера, без исключений:

| Маркер | Значит |
|---|---|
| Иконка/текст без хвостового значка | **Кнопка** — немедленное действие по клику |
| Иконка/текст + `▾` (шеврон вниз) | **Раскрывающийся список** — клик показывает варианты на месте |
| Иконка/текст + `⋯` (многоточие) | **Открывает попап/панель** с расширенными настройками |
| Постоянная видимая рамка + `color.bg.sunken` | **Поле ввода** — отличается от кнопки визуально в любом состоянии, не только при фокусе |

Внутри контекстного меню — отдельный маркер `▸` (шеврон вправо) для вложенного пункта, не путать с `▾` обычного дропдауна.

---

## 8. Мышь: ЛКМ / ПКМ

Жёсткое правило, устраняющее антипаттерн легаси (выбор элемента для рисования требовал ПКМ по иконке):

- **ЛКМ всегда** = основное действие: выбор, активация, перетаскивание, клик по кнопке/пункту. Ни одно обязательное действие не требует ПКМ.
- **ПКМ всегда и только** = открытие контекстного меню. Никогда не несёт иной функциональной нагрузки.

---

## 9. Контекстное меню

- Стандартный пункт: иконка (16px, стиль `affordance.button`) + текст, `space.sm` между ними, выравнивание по левому краю.
- Максимальная вложенность — **1 уровень** через маркер `▸`. `[?требует уточнения — точный список крайних случаев глубже 1 уровня, если PM считает нужным]`
- Исключение из правила «иконка+текст»: стандартный набор copy/cut/paste/delete допускается как **строка иконок без текста**, с тултипом при наведении — только для этого фиксированного набора действий, не general practice.
- Разделитель `color.border.subtle` между смысловыми группами пунктов.

## 12. Разметка (layout)

### 12.1 Боковая панель

`layout.sidebar.expanded` (иконка + текст) ⟷ `layout.sidebar.collapsed` (только иконка) — переключатель всегда доступен, состояние сохраняется между сессиями (см. принципы, `UXP-4`).

### 12.2 Шапка

`[?требует уточнения — рабочее допущение, не финальное решение]` По вашему описанию вы склоняетесь к отказу от постоянной шапки в пользу боковой панели (по образцу OpenAVC, который вам понравился в этой части). Фиксирую как рабочую гипотезу: критическая информация о статусе контроллера и пользователе переезжает в компактную область в верхней части боковой панели, отдельной шапки нет. Если решите оставить минимальную шапку — жёсткое правило независимо от решения: **шапка (или её отсутствие) одинакова на всех экранах без исключений** — это прямое исправление недостатка OpenAVC, где шапка присутствовала не везде.

### 12.3 Разделы приложения

Дашборд / логи и отладка / сетевая конфигурация / конфигуратор проектов — каждый является top-level пунктом боковой панели, доступен в 1 клик, переключение не теряет несохранённые данные (уже гарантировано `NFR-3`/`NFR-4` спецификации `C-PRJ-1`), активный раздел всегда промаркирован состоянием `overlay.selected`.

### 12.4 Различение серверного и панельного проекта

Каждый открытый проект — вкладка в блоке контекста (`BLK-1`). Основной различитель — **отдельная иконка** для серверного и панельного типа (не цвет — держим правило «минимум цветов»). `[?требует уточнения — нужна ли дополнительная тонкая цветовая полоса сверху вкладки, если на прототипе окажется, что одних иконок недостаточно для быстрого различения]`

## 13. Открытые вопросы (сводно)

- Финальный hex акцента — сине-стальной диапазон предложен, не откалиброван по контрасту (WCAG).
- Гарнитура IBM Plex Sans/Mono — предложение, не проверено визуально на кириллице в связке с остальными токенами.
- Шапка vs её отсутствие — рабочее допущение, ждёт вашего решения.
- Различение вкладок серверный/панельный — иконка как основной механизм, цвет как возможное дополнение по итогам прототипа.
- Точные крайние случаи для вложенности контекстного меню >1 уровня и для скролла в попапах.
