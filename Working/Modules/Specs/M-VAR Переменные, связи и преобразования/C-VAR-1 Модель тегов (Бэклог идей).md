# `C-VAR-1 · Модель тегов` Бэклог идей компонента

> **Модуль:** `M-VAR` (Переменные, связи и преобразования) · **Статус:** draft · **Веха:** `В1` → `В2` · **Scope-рефы:** `FM-31, FM-32, FM-33`

## Роли и цели

- **US-a:** Как инженер интегратора, я хочу видеть исторический график изменения значения тега за период, чтобы анализировать поведение оборудования и диагностировать нестабильность без обращения к сырым логам.
- **US-b:** Как инженер интегратора или администратор, я хочу задавать области, из которых тег вообще доступен — везде внутри системы, только скриптам, только через открытый API или нигде извне, — чтобы не открывать управление оборудованием шире, чем требуется на объекте.
  **Примечание:** это не то же самое, что правило доступа «чтение и запись / только чтение» из спецификации (`C-VAR-1/OB-5`). Правило доступа отвечает на вопрос «можно ли писать в этот тег вообще», область доступа — «откуда именно тег виден». Отложено как сложное, с узкими кейсами применения на текущем этапе.

## Observable Behaviors

#### OB-a
  **Дано:** тег отмечен для записи истории значений;
  **Когда:** значение тега обновляется;
  **Тогда:** запись добавляется в историю по одной из двух стратегий — при существенном изменении (deadband — минимальный порог отклонения, ниже которого запись не делается) или через равный интервал времени, в зависимости от настройки тега.

#### OB-b
  **Дано:** тег создан (драйверный, системный или собственный);
  **Когда:** интегратор или администратор задаёт для тега область доступа;
  **Тогда:** доступность тега ограничивается заданной областью (везде внутри системы, только скриптам, только через открытый API, нигде извне) — по умолчанию тег не становится доступен извне без явного решения.
