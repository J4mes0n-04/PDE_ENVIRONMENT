## Роли и цели

- **US-1:** Как IT-служба гос/корп-заказчика, я хочу видеть в каталоге уровень доверия драйвера (например, «сертифицирован» / «проверен»), сверх бинарного «подписан / не подписан», чтобы принимать решения о допуске драйвера осознанно. *(Конкурентный аудит: уровни доверия в каталоге Q-SYS — проверенный факт; enterprise-сигнал.)*
- **US-2:** Как интегратор AV-переговорной, я хочу иметь offline-каталог типовых ИК-команд для распространённого оборудования, чтобы не подбирать ИК-коды вручную. *(Легаси iRidi: облачная база ИК-команд GC Cloud — вердикт «Переосмыслить» в offline-каталог.)*
- **US-3:** Как интегратор, я хочу добавлять драйвер несколькими способами (импорт файла, сканирование сети, из встроенной базы, из другого проекта), чтобы выбирать удобный путь под ситуацию. *(Легаси iRidi: множественные способы добавления драйвера — одна из сильных сторон; частично относится к `C-PRJ-1 — Веб-конфигуратор и сборка проекта`.)*
- **US-4:** Как интегратор, я хочу видеть список поддерживаемого и протестированного оборудования (матрицу совместимости) с версиями прошивок, чтобы снизить неопределённость на этапе проектирования. *(Легаси iRidi: compatibility matrix — вердикт «Сохранить».)*

## Observable Behaviors

#### OB-1
**Дано:** в каталоге присутствует драйвер;
**Когда:** интегратор просматривает его карточку;
**Тогда:** виден уровень доверия драйвера сверх признака «подписан / не подписан». `[?требует уточнения: вводим ли уровни доверия в offline-каталоге и какие именно — решение PM]`

#### OB-2
**Дано:** интегратор подбирает управление для оборудования с ИК-приёмом;
**Когда:** он открывает offline-каталог ИК-команд;
**Тогда:** доступны типовые наборы ИК-команд для распространённого оборудования без обращения к облачному сервису.

#### OB-3
**Дано:** интегратор добавляет драйвер в проект;
**Когда:** он выбирает способ добавления;
**Тогда:** доступны несколько путей (импорт файла, сканирование сети, из встроенной базы, из другого проекта). `[?требует уточнения: часть путей (сканирование сети, из другого проекта) по границе относится к C-PRJ-1 — Веб-конфигуратор и сборка проекта; распределение — решение PM]`

#### OB-4
**Дано:** интегратор проектирует комнату;
**Когда:** он сверяется с каталогом;
**Тогда:** доступна матрица совместимости — список поддерживаемого/протестированного оборудования с указанием версий прошивок.
