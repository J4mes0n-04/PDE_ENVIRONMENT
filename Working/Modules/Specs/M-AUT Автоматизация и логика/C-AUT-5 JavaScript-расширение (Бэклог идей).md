## Роли и цели

- **Б-US-1:** Как инженер интегратора, я хочу, чтобы набор методов программного интерфейса (API) движка постепенно расширялся сверх минимального по мере появления реальных потребностей, чтобы закрывать всё более широкий круг нестандартных задач. *(`FM-106`, `P2` → В4.)*
- **Б-US-2:** Как инженер интегратора, я хочу полноценный режим отладки (debug — пошаговое исполнение с осмотром значений) JavaScript-кода, чтобы находить ошибки в сложной логике. *(Реестр / бэклог `C-PRJ-1` `Б-US-8`; вероятный дом — исполнение, `C-AUT-5`, а не редактор.)*
- **Б-US-3:** Как инженер интегратора, я хочу пользоваться библиотекой подписанных сниппетов (готовых фрагментов кода), а не публичным маркетплейсом, чтобы переиспользовать проверенный код без риска неаудируемых вставок. *(Конкурентный аудит v2.0: ◇ идея, Q-SYS Library / осторожно Node-RED; только подписанные фрагменты, внешний код — предупреждение и аудит.)*
- **Б-US-4:** Как оператор поддержки, я хочу понятную человеческим языком диагностику сбоя скрипта, а не только кодовый уровень, чтобы быстрее локализовать проблему. *(Аналог `C-AUT-4` — Диагностика сценариев, применённый к скриптам.)*
- **Б-US-5:** Как инженер интегратора, я хочу, чтобы устаревшие или не поддерживаемые движком конструкции подсвечивались прямо в уже написанном коде, чтобы находить их до публикации. *(Реестр / бэклог `C-PRJ-1` `Б-US-9`; граница «редактор — контракт движка»: подсветка в коде — редактор `C-PRJ-1`, определение актуальности методов — `C-AUT-5`; предупреждение на публикации уже покрыто спецификацией `C-AUT-5/OB-5`.)*

## Observable Behaviors

#### Б-OB-1
  **Дано:** типовой круг нестандартных задач вырос и минимального набора методов не хватает;
  **Когда:** движок обновляется с расширенным набором методов;
  **Тогда:** новые методы доступны скрипту наравне с прежними, а прежний код продолжает работать (совместимость контракта — `C-AUT-5/NFR-3`).

#### Б-OB-2
  **Дано:** скрипт завершился ошибкой при исполнении;
  **Когда:** оператор поддержки открывает диагностику;
  **Тогда:** причина сбоя доступна в двух видах — понятном пользователю и детальном для инженера, — а не только как кодовый след.
