#  `C-DRE-3 · Пакетирование, подпись и доставка` — Бэклог идей 

> **Модуль:** `M-DRE` (Driver Engine) · **Статус:** draft · **Веха:** пост-`В2` (расширение сверх базового поведения)

## Роли и цели

- **Б-US-1:** Как интегратор, я хочу видеть в каталоге драйверов уровень доверия сверх бинарного «подписан / не подписан» (например «сертифицирован вендором» / «проверен на совместимость»), чтобы выбирать между несколькими драйверами для одного устройства осознанно.
- **Б-US-2:** Как вендор устройства, я хочу иметь возможность зашифровать содержимое драйвера, чтобы защитить код от чтения интегратором, если это требование коммерческого партнёра.

## Observable Behaviors

#### Б-OB-1
  **Дано:** несколько подписанных пакетов драйверов для одного устройства доступны в каталоге;
  **Когда:** интегратор выбирает драйвер для установки;
  **Тогда:** каталог показывает уровень доверия каждого пакета сверх факта подписи (например статус «сертифицирован» / «проверен на совместимость»), присвоенный по итогам отдельной процедуры проверки, не автоматически из факта подписи.

#### Б-OB-2
  **Дано:** вендор публикует пакет драйвера с требованием защиты кода;
  **Когда:** пакет формируется;
  **Тогда:** полезная нагрузка пакета может быть дополнительно зашифрована сверх обязательной подписи — интегратор может использовать драйвер, но не может прочитать его код; манифест при этом остаётся читаемым.
