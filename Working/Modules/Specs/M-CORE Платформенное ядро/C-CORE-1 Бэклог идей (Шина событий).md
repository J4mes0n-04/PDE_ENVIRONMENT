# Спецификация компонента: `C-CORE-1 · Шина событий` — Бэклог идей

> **Модуль:** `M-CORE` (Платформенное ядро) · **Статус:** draft · **Веха:** пост-`В2` (расширение сверх базового поведения) · **Scope-рефы:** трассировка через `DEP-06` (совместно с `C-MON-1`)

## Роли и цели

- **Б-US-1:** Как разработчик модуля-потребителя, я хочу, чтобы шина ограничивала глубину очереди на медленного подписчика, чтобы всплеск телеметрии (частых обновлений состояния) не переполнял память сервера и не превращался в отказ.
- **Б-US-2:** Как разработчик диагностики, я хочу, чтобы повторяющиеся однотипные события об одном и том же состоянии схлопывались в одно, чтобы поток событий не превращался в шум, скрывающий значимые изменения.

## Observable Behaviors

#### Б-OB-1
  **Дано:** один подписчик обрабатывает события медленнее, чем они публикуются;
  **Когда:** очередь необработанных событий для этого подписчика превышает предел `[→ LIM-*]`;
  **Тогда:** система применяет политику ограничения (backpressure — сброс давления на источник) — старые низкоприоритетные события вытесняются раньше управляющих, событие потери фиксируется в диагностике.

#### Б-OB-2
  **Дано:** одно и то же значение состояния публикуется многократно подряд без изменений;
  **Когда:** повторные публикации происходят чаще порога `[→ LIM-*]`;
  **Тогда:** шина схлопывает их в одно актуальное событие для подписчиков телеметрии, не теряя ни одного управляющего (не-телеметрийного) события.
