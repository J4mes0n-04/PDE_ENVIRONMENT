# Спецификация компонента: `C-ROOM-1 · Веб-клиент управления комнатой` — Бэклог идей

> **Модуль:** `M-ROOM — Управление помещением (Client)` · **Статус:** draft · **Веха:** пост-`В2` (расширение сверх базового поведения)

## Роли и цели

- **Б-US-1:** Как пользователь переговорной, я хочу, чтобы клиент запускался быстро и переживал кратковременный разрыв сети за счёт локально закэшированной оболочки интерфейса, чтобы кратковременная нестабильность сети объекта не выглядела как полный отказ.
- **Б-US-2:** Как пользователь переговорной, я хочу иметь возможность переключиться между нативной консолью видеоконференцсвязи (ВКС) и экраном управления комнатой на той же панели одним действием, чтобы не терять доступ к управлению комнатой во время звонка.

## Observable Behaviors

#### Б-OB-1
  **Дано:** клиент открывается на устройстве, где оболочка интерфейса уже была закэширована локально ранее (PWA — Progressive Web App, прогрессивное веб-приложение с возможностью локального кэширования оболочки);
  **Когда:** сеть временно недоступна;
  **Тогда:** клиент показывает закэшированную оболочку и последний известный клиентский проект сразу, помечая данные состояния как неактуальные до восстановления связи с сервером. Само состояние оборудования всегда приходит только с сервера (`INV-1` основной спецификации) — кэшируется только оболочка интерфейса, не состояние. `[?требует уточнения — зависит от решения по веб-технологии, В0]`

#### Б-OB-2
  **Дано:** идёт звонок ВКС, интеграция которого — предмет `C-DRV-6 — Драйверы ВКС`;
  **Когда:** пользователь на панели переключается между нативной консолью ВКС и экраном управления комнатой;
  **Тогда:** переключение происходит одним действием без потери состояния звонка. Сам набор команд управления звонком и его состояние — граница `C-DRV-6`, здесь — только навигационный переход между двумя экранами.
