# AV Control — Реестр сквозных цепочек v1.0

> **Статус:** draft · **Владелец:** PM

## Назначение документа

Реестр фиксирует **сквозные цепочки** — последовательности из нескольких компонентов (в т.ч. из разных модулей), которые реализуют разный функционал, но преследуют единую продуктовую цель. Отдельная спецификация компонента (US/OB/INV/NFR) описывает поведение компонента в изоляции и не обязана раскрывать, как он встроен в более широкий замысел, — этот документ закрывает именно этот пробел.

Это единственный источник истины для описания цепочек. Спецификации компонентов **не пересказывают** содержимое цепочки — они только ссылаются на неё по ID из блока «Связанные цепочки» (см. `ШАБЛОН — Спецификация компонента.md`).

**ID-конвенция:** `CHN-XX`, сквозная нумерация по порядку создания записи (не по волнам, не по модулям).

**Формат записи:**
- **Цель** — 1–2 предложения, почему цепочка существует как единое целое.
- **Компоненты и роли** — таблица: компонент · модуль · роль в цепочке (1 строка на компонент).
- **Последовательность** — текстовая цепочка `А → Б → В`, описательно, без диаграмм.
- **Связанные Б-XX-N** — если для будущего звена цепочки уже есть беклог-запись, ссылка на неё без пересказа; если нет — прочерк.

Статус/веха каждого звена намеренно не дублируются здесь — они уже есть в шапке спеки соответствующего компонента (единый дом факта).

## CHN-01 · Производство и доставка generic-драйверов

**Цель:** обеспечить быстрое производство драйверов для широкого круга устройств без написания кода на каждое устройство — через связку из автоматизированного (AI) производства конфигурации, её контролируемой упаковки/доставки и универсального исполнения в рантайме; с прицелом на будущее открытие этого механизма внешним разработчикам под централизованным контролем версий и качества.

**Компоненты и роли:**

| Компонент | Модуль | Роль в цепочке |
|---|---|---|
| `C-DRV-4` | `M-DRV` | Производит декларативную конфигурацию драйвера — внутренний конвейер (AI Driver Builder), минимальное участие разработчика |
| `C-DRE-3` | `M-DRE` | Упаковывает, подписывает и доставляет конфигурацию, произведённую `C-DRV-4`, до целевого контроллера |
| `C-DRE-4` | `M-DRE` | Исполняет доставленную конфигурацию в рантайме как универсальный (generic) драйвер — сам компонент не пишет код под устройство, только интерпретирует конфигурацию |
| *(будущее, вне текущего Scope)* | — | Внешний контур: расшаривание конвейера производства на сторонних разработчиков, с централизованным контролем версий и качества драйверов |

**Последовательность:** `C-DRV-4` (производство конфигурации, AI) → `C-DRE-3` (упаковка, подпись, доставка) → `C-DRE-4` (исполнение в рантайме) → *(будущее)* внешний контур с версионностью и контролем качества.
